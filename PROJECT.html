Learning plan · P0 and P1 built

Argus turns a UI bug ticket into a verified pull request.

Reproduce the bug, find the source, fix it in a sandbox, check that the fix matches the ticket, and hand it back. Built to learn the agentic layer at architect level, from backend engineering, at $0 and about 20 hours a week.

This folder holds the plan and the P0 and P1 code and runs; P2 to P9 are README stubs. Every results cell stays empty until a run id backs it. The P1 numbers are fixture replay, not a live model. Nothing on this page is a measured number. Same text, as Markdown: PROJECT.md.

What a finished run does

GitHub is the source of truth: issues in, pull requests out. A labelled issue starts a durable workflow. The control plane (FastAPI with DBOS, on Render free, state in Neon free Postgres) treats the webhook as a hint and returns immediately. A reconciliation poller rebuilds state by reading GitHub, because a free Render service can sleep longer than GitHub's 10 second webhook timeout.

The agent job runs on GitHub Actions. From P8 it runs as a reusable workflow inside the tenant's own repository.

1
Reproduce

repro-agent writes a Playwright script from the ticket text, and optionally a screenshot. The script is kept only if it fails on the buggy tree and passes on the golden fix.

2
Locate

A Vite plugin stamps data-src="file:line:col" on JSX host elements in dev and test builds. locate() maps a DOM selector back to a source location, and returns candidates when the mapping is ambiguous. React 19 removed _debugSource, so a build-time attribute is the robust route.

3
Fix

fix-loop is an agent loop written from scratch, with no agent framework. It reads, searches, edits, and submits inside a git worktree mounted in Docker with --network none. Bench checks are read-only. Gates (build, typecheck, lint, unit tests, bench checks) run before submit.

4
Verify

Pixel diff, overflow, new axe-core violations, and new console errors run first. A cross-family vision judge (Gemma, not the Mistral fixer) then asks whether the fix matches the ticket without collateral change. It is a hard gate only if Krippendorff's alpha against hand labels reaches 0.80. Best-of-k (k = 1, 3, 5) picks among candidate patches.

5
Hand back

The workflow waits for a human QA signal: MCP MRTR elicitation (input_required / inputResponses, spec 2026-07-28) or a plain GitHub review comment. The pull request carries the verdict, the judge label, a trajectory link, and before/after screenshots. A backport bot comments instead of forcing when a cherry-pick conflicts.

Traces leave as OTLP spans. Langfuse Cloud Hobby is the default viewer, and an attribute normalizer keeps the backend swappable. A static dashboard on GitHub Pages shows resolve rate, tokens, latency, and trajectory metrics. CI compares a new results file to the stored baseline using confidence intervals, with no model call.

P9, optional and first on the cut list, runs the same loop on a second lane: a Sentry-style error event becomes a failing pytest, then a verified backend fix. Live Sentry is not required.

Constraints

$0

Free and open-source tools only. Every model is open-weight, on a free hosted tier or on the local CPU.

20 hours a week

13th-gen Intel i7-13620H, 16 GB RAM, no discrete GPU, Docker 29.5, WSL2 Ubuntu.

Public code only

Free-tier prompts may be used for training. Only synthetic or public code goes through them. The P8 install target is one of your own public repos.

No framework before the baseline

No agent framework before the P3 loop exists. Adopting one later needs an ADR, measured against mini-swe-agent (ADR-011).

Same scorecard every phase

Each phase ends with an ablation and reports resolve rate, tokens/bug, dollar-equivalent, and p50/p95 latency against the previous phase. Each phase starts by re-checking pinned versions.

Empty until measured

A results cell stays “—” until a run id backs it. Ablation tables in the phase files ship blank on purpose.

Shared types and the loop

  • Ticket. The bug report: text, and optionally a screenshot.
  • Task. Ticket, bug patch, golden patch, checks, and meta. Valid only when checks fail on the buggy tree and pass on the golden tree.
  • Trajectory. One record per step, with tokens in, out, and cached, plus a stop reason. A recorded trajectory replays with no model call.
  • Fix tools. read_file, list_dir, search, edit, run_cmd, submit, plus ast-grep. Repro tools: navigate, snapshot, click, type, assert-visible, screenshot. locate() is its own MCP server.
  • Stop conditions. submit, step cap, token cap, QuotaExceeded, or stuck detection. Malformed arguments return a typed error to the model.
  • Context strategies. None, output caps, offload-to-files, rolling summary. The manager switches strategy at 80% of the window.
  • Quota ledger. Hard-stops before an HTTP request would cross a measured daily cap. Cached tokens are counted apart. State survives a restart. From P8 the key includes a tenant id.

Metrics contract

Every phase reports these four numbers on the same evaluation set, against the previous phase.

MetricDefinition
Resolve rateResolved over attempted, Wilson 95% interval. Resolved means the scorer passes, no bench check file was touched, and from P4 the verifier accepts. Exit 2 and quarantined tasks are excluded from attempted
Tokens/bugMean of input, output, and cached tokens, summed over every agent, retry, judge call, and best-of-k sample. Reported separately
$-equivalentTokens times list prices in prices.json (URL and date per model). A comparison unit, not money spent. P0 through P4 leave this cell as "—" until P5-T11
Latency p50 / p95Wall-clock from task start to final patch. Time waiting for a quota reset is excluded and reported separately
  • Ablations use a 30-task stratified subset. P8's single-vs-multi comparison uses 20 tasks.
  • Every run records model, host, seed, prompt hash, and git commit.
  • A difference smaller than the Wilson interval is reported as no difference.
  • From P5, docs/metrics.md fixes trajectory formulas: steps, tool-error rate, redundant-call rate, stuck rate, recover-after-gate-failure rate.

P0 · weeks 1–4 · 76 h · argus-core, target-app, bench, bugsmith

A benchmark that scores a fix with no model in the loop

Golden-fix CI passes on all 30 hand-seeded tasks with zero model calls. bugsmith emits 300 or more tasks that fail checks before the fix and pass after, and two runs with the same seed hash identically. Six UI archetypes, three difficulty tiers, ten seeded tasks per tier. Flake detection runs each check five times and quarantines mixed results. The ledger refuses an over-cap call before any HTTP request. ADRs 001–003.

P1 · weeks 4–6 · 32 h · repro-agent

A ticket becomes a Playwright script that fails on the bug

A spike calls Playwright MCP from MCP Python SDK v2 and writes a go or no-go. If it is no-go, direct Playwright is the tool (ADR-004). The loop generates, runs, and revises, with a hard retry cap. The verifier returns valid, passes-on-bug, fails-on-golden, or error. CI replays fixtures with no model calls. ADRs 004–005.

P2 · weeks 6–8 · 44 h · dom2src-plugin, dom2src-mcp

A rendered element maps back to a file and line

data-src is on every JSX host element in dev and test, and absent from production. locate() errors are not-found, ambiguous, or no-source-info. Wrappers return ranked candidates. Compared against a repo-map plus LSP, and against pgvector with a local embedding model, on top-1 file accuracy. ADRs 006–007.

P3 · weeks 8–12 · 84 h · fix-loop

The loop, written from scratch, inside a sandbox

The largest phase. A git worktree per task, Docker with --network none, CPU and memory caps, checks read-only. Four context strategies on the same 30 tasks, then mini-swe-agent on those tasks with the same model. A recorded trajectory replays byte for byte. CI fails if an agent framework appears in the dependencies. ADRs 008–011.

P4 · weeks 12–16 · 72 h · verify

Did the patch fix the bug, and only the bug

Checks run in a fixed order and short-circuit. You label 100 pairs before seeing any judge output. Target agreement is Krippendorff's alpha of at least 0.80, with a bootstrap interval. If the budget runs out below that, ADR-013 makes the judge advisory only. A Mistral vision judge is the self-preference control. Best-of-k at k = 1, 3, and 5. k = 5 is the biggest quota consumer, because it multiplies fixer calls by five. ADRs 012–014.

P5 · weeks 16–20 · 64 h · eval, dashboard · buffer week 17

How the agent got there, and whether routing is worth it

OTel GenAI spans, still a development spec, plus a normalizer so Langfuse and a local Phoenix can show the same run. The router is data: cheap tier for repro and localize, strong tier for fix. The system prompt is a byte-stable prefix so caching can hit. CI fails when resolve rate drops below the baseline's lower bound. A SWE-bench Multimodal subset of 10 to 20 tasks is adapted in; exclusions are listed. Dashboard on GitHub Pages. ADRs 015–017.

P5.5 · weeks 20–21 · 28 h · skills/

Skills from successful runs, and a poisoned skill that cannot take over

At least five reviewed skills in the agentskills.io format. The loader shows name and description only, and loads the body on demand. Distilled from a train set that does not overlap the 30-task held-out subset. Trust controls: review flag, content-hash pin, per-skill tool allowlist. ADRs 018–019.

P6 · weeks 22–24 · 52 h · flow · hard cut line

A durable workflow that survives crashes, sleep, and lost webhooks

DBOS checkpoints each step. Opening a pull request is find-or-create, keyed by ticket id. The webhook checks HMAC, enqueues a reconcile, and returns 202. The poller rebuilds state from the issue, the PR, and the Actions run. QA waits until approve, reject, or timeout. Render cold start is measured against the 10 second timeout. Neon CU-hours are measured over 48 hours against the 100 CU-hour monthly free limit. DBOS vs Temporal is written, not built. ADRs 020–023. Stopping here is still a deployed core.

P7 · weeks 24–27 · 44 h · guard · buffer week 25

Threat model, red team, and three sandbox tiers

ASI01 through ASI10, each with a threat, a control, and a residual risk. Secrets stay out of prompts, logs, trajectories, and traces. The App token is least-privilege and short-lived. The audit log is append-only and hash-chained. promptfoo covers injection via ticket, repo file, and skill. Escape probes: network, host filesystem, Docker socket, metadata address, fork bomb, symlink. Tiers: Docker, gVisor, Firecracker on the Actions KVM runner. ADRs 024–026.

P8 · weeks 27–30 · 60 h · app

A public GitHub App. The job runs in the tenant's repo

A reusable workflow keeps the code and the tenant's secrets off your servers (ADR-027). Config is .argus.yml. Intake starts on a label, and ignores it when the actor lacks write access. The PR body has the verdict, judge label, trajectory link, and two screenshots. The backport bot comments on conflict. A planner plus subagents is kept only if it wins on both resolve rate and tokens (ADR-029). Demo install is one of your own public repos. The video, under four minutes, shows a success, a verifier rejection, and a quota refusal. ADRs 027–029.

P9 · weeks 30–32 · ~40 h · optional, cut first

The same loop, on a backend bug, to see what was actually shared

A small FastAPI app (auth, CRUD, one background job) gets Python mutations. An exported Sentry event becomes a Ticket. No live Sentry. The repro step is a pytest, reusing the P1 verifier. The P3 fixer is reused with a pytest gate. No copy of the P3 code. Email and bearer tokens are redacted before any model call. A script reports reuse by module and by lines. ADR-030.

Risks, and what gets cut

#RiskMitigation

2The open-weight fixer resolves too few bugs for ablations to show a signalDifficulty tiers, confidence intervals, a 30-task subset
3Neon compute and Render sleep collide with DBOS pollingMeasure in P6. ADR-021 and ADR-022
4Playwright MCP may not speak the 2026-07-28 specP1 spike. Fallback is direct Playwright as a tool
5Seven months at 20 hours a weekHard cut after P6. Buffer weeks after P4 and P6

Cut in this order

  1. P9, the whole backend lane
  2. P8 multi-tenancy, down to a single-tenant App
  3. P5.5, skills
  4. Firecracker, reduced to an ADR plus a gVisor measurement
  5. MRTR elicitation, replaced by review comments
  6. SWE-bench Multimodal, keeping the synthetic set only

Never cut: the P3 loop, the P4 judge calibration, bugsmith, the P5 OTel work, or best-of-k.

Three tasks most likely to force a redesign

  1. P0-T24, the bugsmith validity filter. The 300-task set depends on it keeping only mutations that fail before and pass after.
  2. P4-T14, judge calibration. Alpha of 0.80 on CPU may not be reachable. ADR-013 is the advisory-only fallback.
  3. P6-T12 and P6-T14, DBOS on Render and Neon. The CU-hour measurement may force a different poll cadence.
