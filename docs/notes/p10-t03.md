## The gap

Acceptance criterion: "the stored ticket directory passes `bench validate`".

- `bench validate <dir>` (`argus_bench.task_dir.load_task_dir`) reads `ticket.json`, `checks.json`, `meta.json`, `bug.patch` and `golden.patch`, and checks that the screenshot file named in the ticket exists.
- The run folder the form stores holds `ticket.json`, `intake.json`, `state.json` and `shots/screenshot.<ext>`. A bug report has no patches or checks, so `bench validate` on the bare run folder fails (the test pins this: exit 1).
- What was seen holding: copy the stored `ticket.json` and `shots/` next to the four task-only files of the seeded BUG-17 task and run the real validator. It prints `valid <dir>` (checked with the `bench` function in a test, with `python -m argus_bench.cli validate`, and once by hand on a folder made by the page in a browser). Removing the screenshot makes it fail, so the validator does look at the stored screenshot path.
- So the ticket part of the stored folder is what the validator accepts. Whether that meets the criterion is a call for the owner: if yes, tick the box; if the criterion means the bare folder must pass, the task rows need a change (a ticket-only validate mode in bench), which this task did not make because bench is another phase's package.

## Not built, on purpose

- The "service waking" state (Render cold start): the workbench is local, there is no cold start.
- Duplicate-submit dedupe by ticket id (P6-T06 style): two submits make two runs; the page disables the button while a request is open. Needs the runner's workflow id.
- Image decoding: PNG or JPEG is decided by the first bytes only (the spec says magic bytes). A file with a valid header and junk after it is stored; nothing in T03 serves it back.
- The upload cap uses the Content-Length header (411 when absent) because Starlette spools a multipart body before the route runs.
- A browser turns a newline in the textarea into CRLF in a multipart body, so text typed in the page is stored with CRLF line breaks.
- `shop-ui` is in the spec's repo list with `built: false`; it is accepted (the brief says the allowed list is the spec's `repos`) and marked "[not built here]" in the select.
