# P8-T10 Backport bot with conflict handling

Code: `packages/app/src/argus_app/backport.py` (new), `create_draft_pr(..., base=None)` in `packages/flow/src/flow/github_write.py` (one optional argument). Tests: `packages/app/tests/test_backport.py` (54 cases). They use real `git` on local bare repositories in a temp folder and the stateful `FakeGitHubApi`; no network, no model. A spy runner records every git argument list, so the tests state what the bot never ran.

## What it does

On a merged Argus fix PR (`pull_request` closed, `merged` true, title and head branch agree, `flow.review_comment.ticket_of_pr`):

1. Branch name `argus/backport-<pr number>-to-<hash of target>`. Look the PR of that head up first (any state). Found: `exists`, no git command runs. Lookup error: raises, nothing cloned or created.
2. Temporary clone on the target branch (empty home, no system config, empty hooks folder, no prompts, a short environment).
3. The merge commit must be an ancestor of `origin/<PR base>`. A PR head (a fork, an unmerged branch) or a commit not in the repo raises `Refused`; nothing is picked.
4. `git cherry-pick -x <sha>` on a new branch (`-m 1` for a merge commit).
5. Conflict: `git cherry-pick --abort`, one comment on the merged PR (target, commit, conflicted files, how to do it by hand). The comment carries a key marker, so a second run does not comment again. No push, no PR, no branch change. `conflict`.
6. Clean: plain `git push origin <branch>`. Push failed: `push-failed`, no PR (the remote branch is not what this run made), no retry. Branch already on the remote with the same tree (an earlier run pushed, then failed to open the PR): no second push, the PR is opened from it. Different tree: `stale-branch`, nothing is done.
7. Open a draft PR with base = the target and comment its link on the merged PR. `opened`.

## Criteria and the test for each

| Criterion | Test |
|---|---|
| On a merged fix, a backport PR to the configured branch | `test_a_merged_fix_opens_a_backport_pr_to_the_configured_branch`, `test_a_merge_commit_is_picked_with_the_first_parent` |
| On conflict it comments and does nothing destructive | `test_a_conflict_is_commented_and_nothing_is_changed` (all refs of the bare origin equal before and after, no push, no PR, `--abort` ran), `test_a_conflict_is_commented_once_across_runs` |
| No force-push, no deletion, no reset | the spy checks every call of every test against a forbidden list; `check_args` refuses `--force`, `-f`, `--force-with-lease`, `--delete`, `-D`, `+ref`, `:ref`, `reset`, `clean`, `rebase`, `fetch`, `branch` (`test_check_args_refuses_destructive_and_pr_head_commands`) |
| No retry of PR creation from a stale branch | `test_a_failed_push_creates_no_pr` (one push, no PR), `test_a_stale_branch_on_the_remote_is_left_alone`, `test_a_pr_that_failed_after_the_push_is_opened_from_the_same_branch_without_a_second_push` |
| Never check out a PR head under the installation token | `test_a_commit_that_is_not_in_the_base_history_is_refused`, `test_the_head_ref_and_head_sha_of_the_pr_are_kept_away_from_git`, the `refs/pull` refusal; the token reaches git only as `http.extraHeader` in the environment, for `https://` URLs, never in an argument (`test_the_token_is_in_the_environment_for_https_only_and_never_in_an_argument`) |
| Refuse a tenant-supplied conflict command | `BackportConfig.from_mapping` raises `ConflictCommandRefused` for every name in `COMMAND_FIELDS`; no process is started (`test_a_conflict_command_from_the_tenant_is_refused`) |
| A second run finds the existing PR or no-ops | `test_a_second_run_finds_the_existing_pr_and_runs_no_git`, `test_a_lookup_error_runs_no_git_and_creates_nothing` |
| Other events | `test_events_that_are_not_a_merged_argus_fix_start_nothing` (no git, no GitHub call) |

The configured branch is a `BackportConfig(target_branch)`, from a mapping or from `ARGUS_BACKPORT_BRANCH`. It is not a field of `.argus.yml` (the T05 model refuses unknown fields and T22 pins it).

## Not done, not verified

- Not run against the real GitHub: no real installation token, no HTTPS clone, no real push, no webhook delivery. The `http.extraHeader` basic-auth form is the one GitHub documents for installation tokens (`x-access-token:<token>`); it was not tried here.
- Not wired: `flow.webhook` has no `pull_request` closed hook that calls the bot, and the Render image is not known to have `git`. A caller passes the payload.
- A rebase-merge of several commits only backports the last commit (GitHub's `merge_commit_sha` is that one).
- The backport PR is always a draft; which branch the tenant workflow may test is ADR-027 (written separately).
- T23 (break it) will probe this module; the refusals above are the behaviour it should find.
