# P10-T14 End-to-end browser run

Status: done. Every acceptance criterion was seen holding in this run (a real browser, a real server), and the HTTP-level walk exists as a test.

## How it was run

- Server: `uv run --all-packages python -m argus_workbench.cli serve --port 8765` (the `argus-workbench.exe` launcher is blocked by Windows Application Control on this machine, error 4551, so the module form was used; it is the same `cli.main`). `ARGUS_WORKBENCH_RUNS` pointed at a throwaway folder in the session scratch directory, `ARGUS_WORKBENCH_LEDGER` at a file that does not exist. The tick was the UI default, 700 ms (the CLI has no tick option, and none was added).
- Browser: Playwright MCP (Chromium). Desktop 1280 x 900 and a 375 x 812 viewport.
- The Playwright browser turned out to be shared with other task sessions: one of my early tabs was driven to another page by someone else (the issue form suddenly held the BUG-17 ticket). From then on the scenario walks and the 375 px shots ran in their own isolated browser context, created and closed inside one script, so nothing else could touch them. The first walk (issue, run, review, approve, PR, history, normal scenario) was done by clicking in the shared tab before that happened and was checked by its result (run id `run-d21f3026703d`, decision approve, PR draft, history row `done / approve / yes`).
- The screenshot tool only writes inside the main checkout, so shots were saved there as scratch and moved by hand into `packages/workbench/docs/shots/`; the scratch folders were removed. Nothing else in the other checkout was changed.
- Stopped afterwards: the server process was ended, port 8765 has no listener (only a TIME_WAIT socket was left).
- No model was called. Every run is SIMULATED.
