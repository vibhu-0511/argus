## What is built and tested here (no network)

- `argus_core.telemetry.trace_config()` reads the export settings from environment variables. `start_tracing()` with no argument uses it.
- A missing key raises `TraceConfigError`, and the message names the variables, never their values.
- The Langfuse request goes to `<host>/api/public/otel/v1/traces` with `Authorization: Basic base64(public:secret)` and `x-langfuse-ingestion-version: 4`. A test points the exporter at a local HTTP server and checks the path and both headers on the wire. It does not prove Langfuse accepts them.
- Network exports use a batch processor: queue of 512 spans, one batch holds the whole queue, one export gives up after 3 seconds (retries share that budget). A test points the exporter at a port that accepts and never answers: emitting 1,024 spans takes well under 2 seconds, and with the test's 1-second timeout the whole run, shutdown included, took 2.1 seconds. T25 breaks this on purpose; the numbers there are the evidence.
- A test turns on debug logging, makes an export fail, and checks that neither key nor the Basic string is in the log. `repr(TraceConfig)` hides the headers.
- Keys live in the process environment only. Nothing writes them to a file, a log line or a span.

## Environment variables

| Variable | Meaning |
|---|---|
| `ARGUS_TRACE_BACKEND` | `console` (default, prints spans), `langfuse`, or `otlp` (any OTLP/HTTP receiver) |
| `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` | Required for `langfuse`. Project keys (`pk-lf-...`, `sk-lf-...`) |
| `LANGFUSE_BASE_URL` (or `LANGFUSE_HOST`) | Optional. Default `https://cloud.langfuse.com` (EU). US: `https://us.cloud.langfuse.com`. Also JP and HIPAA regions exist |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` / `OTEL_EXPORTER_OTLP_ENDPOINT` | For `otlp`. The first is used as given, the second gets `/v1/traces` added |
| `OTEL_EXPORTER_OTLP_TRACES_HEADERS` / `OTEL_EXPORTER_OTLP_HEADERS` | For `otlp`. `name=value,name=value` |

Endpoint form checked on 2026-11-01 against <https://langfuse.com/integrations/native/opentelemetry>: base `https://cloud.langfuse.com/api/public/otel`, traces `.../api/public/otel/v1/traces`, Basic auth with the two keys, HTTP/protobuf or HTTP/JSON only (no gRPC), and the `x-langfuse-ingestion-version: 4` header so data shows up at once instead of up to 10 minutes late.

## What you must do to finish the check

1. Go to <https://cloud.langfuse.com> (or the US site), sign up, and create an **organisation** on the **Hobby** plan and a **project**. Note which region you picked.
2. In the project, open Settings, API Keys, create a key pair. Copy the public key (`pk-lf-...`) and the secret key (`sk-lf-...`) now; the secret is shown once.
3. In the shell you will run the command from, set the variables (PowerShell shown; do not put them in a file in the repo):

   ```powershell
   $env:ARGUS_TRACE_BACKEND = "langfuse"
   $env:LANGFUSE_PUBLIC_KEY = "pk-lf-..."
   $env:LANGFUSE_SECRET_KEY = "sk-lf-..."
   # US region only:
   $env:LANGFUSE_BASE_URL = "https://us.cloud.langfuse.com"
   ```

4. Send one small test trace. From the repo root:

   ```bash
   uv run --package argus-core python -m argus_core.telemetry
   ```

   Expected last line: `backend=langfuse endpoint=https://.../api/public/otel/v1/traces export=SUCCESS`. `export=FAILURE` means the keys, region or network are wrong (the reason is logged, without the keys).
5. In the Langfuse project open Tracing. Within a few seconds you should see a trace with the session `argus-smoke`: an `invoke_agent argus-smoke` span with a `chat smoke-model` and an `execute_tool smoke-tool` child. If it is there, T07's check holds for the smoke trace; tick the T07 box and tell me what the tree looked like.

Not done by this task: a trace of a real fix-loop run. Nothing in the repo calls `start_tracing()` during a real run yet. Wiring that and showing one real run in Langfuse is T23.

## Things to know

- Hobby: 50,000 units a month (a trace, an observation or a score is a unit), 30 days of data, 2 users (`docs/notes/p5-t00-versions.md`). What happens after 50,000 units is not stated on the pricing page.
- The Langfuse profile of the normalizer (T08) renames `argus.usage.cost_usd` to `gen_ai.usage.cost`, which Langfuse reads as the cost. Without it the cost is not shown.
- The Langfuse docs say that spans sent straight over OTLP put unmapped attributes under `metadata.attributes`, where they cannot be filtered. T08 adds the `langfuse.observation.metadata.` prefix to the argus-owned ones.
