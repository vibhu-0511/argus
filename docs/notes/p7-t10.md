## Owner steps on a real Linux host

Needs: Linux 5.6+ (x86_64 or ARM64), Docker Engine, `sudo`, this repo checked out, `uv` and Python 3.12. KVM is optional for gVisor (T00); this note does not use the KVM platform, so `runsc` runs with its default platform. Record which one it uses (`runsc --version` does not say; `docker run --rm --runtime=runsc alpine dmesg` shows the boot lines).

1. Install `runsc` from the release tarball with its checksum (T00: `runsc install` no longer auto-downloads since the end of September 2026). The pin in T00 is `release-20261026.0`; gVisor ships about weekly, so you may pick a newer one, but write down which. Assets are `gvisor-x86_64.tar.bz2` (or `gvisor-aarch64.tar.bz2`) and `SHA256SUMS` at `https://github.com/google/gvisor/releases/tag/release-20261026.0`. I did not download the tarball, so its inside layout is not checked: find the `runsc` file after extracting. The apt repository in the [install guide](https://gvisor.dev/docs/user_guide/install/) is the other option.

   ```bash
   REL=release-20261026.0; ARCH=x86_64
   curl -fsSLO "https://github.com/google/gvisor/releases/download/$REL/gvisor-$ARCH.tar.bz2"
   curl -fsSLO "https://github.com/google/gvisor/releases/download/$REL/SHA256SUMS"
   sha256sum -c --ignore-missing SHA256SUMS
   mkdir gvisor && tar -xjf "gvisor-$ARCH.tar.bz2" -C gvisor
   sudo install -m 0755 "$(find gvisor -name runsc -type f | head -n 1)" /usr/local/bin/runsc
   runsc --version
   ```

2. Register it with Docker. The install guide's command is `sudo /usr/local/bin/runsc install`; it adds a `runsc` entry under `runtimes` in `/etc/docker/daemon.json`. Then restart Docker (the guide says `reload`; a restart is safe) and look at the result:

   ```bash
   sudo /usr/local/bin/runsc install
   sudo systemctl restart docker
   cat /etc/docker/daemon.json
   docker info --format '{{json .Runtimes}}'
   docker run --rm --runtime=runsc hello-world
   ```

   `daemon.json` should hold a `runsc` runtime whose `path` is `/usr/local/bin/runsc`. If `runsc install` is not available, add that entry by hand. That form is from my memory of the gVisor docs, not re-read today.

3. Run the fixture task and the escape suite, and keep both result files:

   ```bash
   uv sync --all-packages --locked
   uv run --all-packages guard sandbox-run --runtime runsc --out packages/guard/results/sandbox-run-runsc.json
   uv run --all-packages guard escape --tier gvisor --out packages/guard/results/escape-gvisor.json
   ```

   The first command overwrites the "unavailable" file from this machine. `status` must be `pass` and `docker_runtimes` must list `runsc`. Check `stdout` for the kernel and `dmesg` lines; if `uname` still shows the host kernel and `dmesg` shows no gVisor lines, the container did not run under gVisor and the result is not valid. To run any fix-loop command under gVisor, set `ARGUS_SANDBOX_RUNTIME=runsc`.

4. Commit the JSON files. Tick T10 only if the `runsc` result file says `pass` and shows `runsc_version`. Put the `runsc --version` text and the release you installed in the commit message or here.
