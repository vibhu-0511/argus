## The one computed figure: held-out tasks the skills are about

The T03 note says T08 should report per archetype; T08 did not. This reads the stored files and groups the 29 runnable held-out tasks by the `archetype` in each seeded `meta.json`, with the T08 pairing rule (a task `excluded` in either row is left out of the pair):

```python
import json, pathlib, collections
root = pathlib.Path("packages")
tasks = [t["id"] for t in json.load(open(root/"skills/split.json"))["held_out"] if t["runnable"]]
rows = collections.defaultdict(list)
for t in tasks:
    arch = json.load(open(root/f"bench/tasks/seeded/{t}/meta.json"))["archetype"]
    a = json.load(open(root/f"eval/results/t14/A/{t}/verdict.json"))["verdict"]
    s = json.load(open(root/f"eval/results/t08/S/{t}/verdict.json"))["verdict"]
    rows[arch].append((t, a, s))
for arch, rs in sorted(rows.items()):
    paired = [r for r in rs if "excluded" not in r[1:]]
    print(arch, len(rs), sum(r[1] == "resolved" for r in paired), sum(r[2] == "resolved" for r in paired), len(paired), [r for r in rs if r[1] != r[2]])
```

Output on 2026-11-03 (archetype, tasks, resolved without, resolved with, paired, tasks whose verdict differs):

`font-size` and `missing-style` are the two labels the skills were drawn from: 9 tasks, 4 resolved in both rows, 5 in neither, no task differs. That is the "4 and 5" in the ADR. The label is the generator's, as in the train set, so it has the same weakness (it is not the ticket type); the 9 tasks are the closest match to the train labels, not proof that the skills apply to them.
