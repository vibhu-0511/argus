# P7-T12 Escape-test suite

Command: `guard escape --tier docker|gvisor|firecracker [--runtime NAME] [--launcher "CMD"] [--timeout S] [--out FILE]`. Code: `packages/guard/src/guard/escape.py`, registered in `cli.py` (4 added lines). On this machine `pytest.exe` and the `guard` script are blocked, so I ran it as `uv run --all-packages python -c "import sys; from guard.cli import main; sys.exit(main(sys.argv[1:]))" escape --tier docker`.

## How a probe works

- Each probe is a shell script run inside the sandbox. It prints `BLOCKED ...` (pass), `ESCAPED ...` (fail) or `ERROR ...` (could not tell). No verdict line, a timeout or a launcher that cannot start is an **error**, never a pass.
- Exit code: 0 all pass; 1 any fail or error; 3 tier not available.
- Containers use the fix-loop flags (`fix_loop.sandbox`: image, `--network none`, 1 CPU, 512 MB, work rw, checks ro) plus `--pids-limit 128`. Names are `guard-esc-<probe>-<random>`; each is removed with `docker rm -f` after its probe. Only two folders in one temp dir are mounted; the docker socket is never mounted; no `-e` is passed (the launcher process has a fake `ARGUS_MODEL_API_KEY`, to prove it does not leak).
- The TCP, HTTPS and DNS commands are the ones from `guard.egress` (T05), so the T05 control run covers them.

## Probes (12)

| Probe | Blocked means | 
|---|---|
| network-tcp, network-https, dns-lookup | no TCP, HTTPS or resolver answer from an external IP or name |
| metadata-address | `169.254.169.254` does not answer |
| host-fs-read | a host file (not mounted) holding a random token cannot be read at its host path or the Docker Desktop and Linux host-mount spellings (6 paths) |
| readonly-mount-write | write, create and delete in `/checks` all fail and `keep.txt` is unchanged |
| docker-socket | no socket file at `/var/run/docker.sock`, `/run/docker.sock`, `/docker.sock` |
| fork-bomb | a bounded loop of 300 background processes stops at or below the pids limit 128 |
| symlink-escape | a symlink created in `/work` to the host folder (6 spellings), read through, finds nothing |
| env-no-secrets | no variable holds the fake secret and none is named like a key, token, secret or password |
| host-proc | the container sees its own pid namespace: at most 20 processes and pid 1 is the probe shell |
| mount-syscall | `mount -t tmpfs` is refused |

The "fork bomb" is a bounded loop (300 sleeps), not an exponential bomb: even with no cap it stops at 300, so it cannot hurt the host, and the hard timeout plus `docker rm -f` back that up.

## Finding: the fix-loop sandbox has no pids limit

The fork-bomb pass depends on `--pids-limit 128`, which **the suite adds and `fix_loop/sandbox.py` does not set**. I ran the same probe through `fix_loop.sandbox.run` (the real fix-loop flags): `ESCAPED 301 processes alive, no cap`. So the real fix-loop container can start 300 processes today; only the 30 s tool timeout and the 512 MB memory cap stop a real fork bomb. Fix (not made here, it is outside T12): add `--pids-limit` to `sandbox.run`, then the suite's added flag can go. This matches the open item in the threat model (section 5 ASI02, section 7).

## Do the probes fail when they should? (seen)

The Docker test `test_probes_can_fail_when_the_sandbox_is_weakened` weakens the container on purpose and requires a **fail** from: host-fs-read and symlink-escape (host folder mounted at a host-mount path), env-no-secrets (`-e` of the fake key), fork-bomb (`--pids-limit 100000`), host-proc (`--pid host`), mount-syscall (`--cap-add SYS_ADMIN`). It passed. Not given a positive control: readonly-mount-write, docker-socket (I will not mount the socket), metadata-address; the network probes by the T05 control run.

## Other tiers

- `--tier gvisor`: needs a Docker runtime named `runsc` (override with `--runtime`). Here it is not registered, so the output is "tier not available here ... No probe ran. This is not a pass." and the exit code is 3. The `--runtime` path is only unit-tested (the argument list is checked); it never ran against gVisor.
- `--tier firecracker`: needs `--launcher` (or `ARGUS_FIRECRACKER_LAUNCHER`), a command prefix that receives `sh -c <probe>` and must give the guest `/work` (rw) and `/checks` (ro, holding `keep.txt` = `same`). Without it, same "not available" output. The contract is my guess for T11 to confirm or change. Tested only with a stub that prints `BLOCKED`, which proves the protocol and nothing about Firecracker.
- Tests: no Docker needed for the table, the printing, the verdict parser and the unavailable paths. Two tests are marked `docker` and skip when the daemon is down.

## Not verified

- IPv6 and ICMP are not probed.
