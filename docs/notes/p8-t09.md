# P8-T09 PR creation with verdict, trajectory link and screenshots

Code: `packages/app/src/argus_app/pr.py` (new), `HttpGitHubClient.update_pr` in `packages/flow/src/flow/github_write.py` (new method). Tests: `packages/app/tests/test_pr.py` (30 cases), two more in `packages/flow/tests/test_github_write.py`. Mock GitHub (`FakeGitHubApi`, an httpx MockTransport), no network, no model.

## Every clause of the task row

| Clause | How | Test (in `test_pr.py`) |
|---|---|---|
| Body has the verifier verdict | table row from `verdict.json` of the verify step (`ok`, or `failed_check: first_failure`) | `test_the_body_has_verdict_judge_label_trajectory_and_two_screenshots`, `test_a_rejected_verdict_is_written_as_it_is` |
| Judge label | row from `judge.json` `{"label"}` (`pass`, `fail`, `collateral`, `error`), "not run" if the file is absent; any other value is refused | same, `test_the_evidence_files_are_checked` |
| Trajectory link, two screenshots | links given by the caller; refused unless a plain `https://` URL; a screenshot link counts only if its PNG is in the verify folder; a missing one is written "not available" and gets no image | `test_a_missing_judge_or_screenshot_or_link_is_not_made_up`, `test_a_link_without_its_png_is_not_used`, `test_a_link_that_is_not_a_plain_https_url_is_refused` |
| Built through the API, title and body as JSON fields | `create_draft_pr` posts `json={"title","head","base","body","draft"}`; the test reads the sent request and checks the content type and the field set | `test_title_and_body_are_json_fields_and_a_command_substitution_is_not_executed` |
| `$(...)` is not executed | `subprocess.*`, `os.system`, `os.popen` are replaced by functions that fail the test; a hostile issue title and a hostile ticket id go through; no file appears; a source scan finds no `subprocess`, `shell=`, `eval(` in `pr.py` or `github_write.py` | that test, `test_a_title_with_a_command_substitution_in_the_ticket_id_is_text`, `test_no_module_on_the_path_builds_a_command_line` |
| One stable branch | `flow.states.branch_name(ticket)`, the same for push, find and create | `test_one_stable_branch_and_one_pr_across_runs` |
| One creator, not the agent | `creator_client(ScopedToken)` holds the App installation token of the repo; every request carries that one `Authorization`; agent-side env tokens are never used; a scan shows `fix-loop` and `repro-agent` sources have no GitHub write code | `test_every_call_is_made_by_the_one_creator_with_the_app_token`, `test_the_agent_code_cannot_write_to_github` |
| Draft until QA | created with `draft: true`, never marked ready here (no GraphQL call) | `test_it_is_draft_and_never_marked_ready` |
| No PR when the patch is empty | returns `None` before any call, also for whitespace; an existing PR is left alone | `test_no_pr_when_the_patch_is_empty`, `test_an_empty_patch_leaves_an_existing_pr_alone` |
| A lookup error leaves the existing PR untouched | the lookup comes first; on error nothing is pushed, created or edited | `test_a_lookup_error_creates_nothing_and_touches_nothing`, `test_a_lookup_error_leaves_the_existing_pr_untouched` |
| Re-running updates the same PR | find by head (`state=all`), then `update_pr` PATCHes title and body; unchanged text is not written; a closed PR is not edited | `test_a_rerun_updates_the_same_pr`, `test_a_rerun_with_the_same_evidence_writes_nothing`, `test_a_closed_pr_is_not_edited_or_reopened` |

The body writes the issue title inside a code span after collapsing newlines, removing backticks and running `argus_core.redact`, so a title cannot add table rows, mention people or carry a token (`test_issue_title_cannot_break_out_of_the_code_span_or_leak_a_token`). The PR title stays `Argus fix for <ticket>` because `flow.review_comment.ticket_of_pr` reads the ticket back from it.

## Interface assumptions (not verified against a real run)

- `judge.json` is not written by any step today. `verify.judge.JudgeResult.label` has the right values; whoever runs the judge saves `{"label": ...}` next to `verdict.json`. Without it the body says "not run".
- The artifact URLs (trajectory, screenshots) come from whatever uploads them. The tenant runner (`argus_app.runner`) makes no screenshots yet, so a real tenant PR will say "not available" for them until P8-T16 decides where they are stored. A PR body cannot embed a private Actions artifact.

## Not done

- `flow.workflow.open_pr_step` still opens the PR with its generic body (`find_or_create_pr`). `open_or_update_pr` is not called by the running workflow; wiring it needs the verify folder and the artifact URLs to travel from the Actions artifact into the step. Nothing about that is a criterion of T09, but T16 needs it.
- Not run against the real GitHub or a real App token.
- A re-run with a different patch updates the body, not the branch (the push key is per ticket, attempt 1).
