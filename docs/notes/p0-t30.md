# P0-T30: quota exhausted mid-run

## Induced failure

The daily request cap for `openai/gpt-oss-20b` was set to one. `baseline_many` was started over `task-a` and `task-b`. The model call was a local stand-in. No HTTP client ran.

## Signal observed

`QuotaExceeded` was raised before the next task. The stand-in was not entered for `task-b`, so that request did not run. The run halted. The partial file already held `task-a` and its patch text.

## Fix

A later run reads that partial file and skips finished task ids. A clock on the next calendar day makes the ledger roll the day and allow another request. The remaining task then runs, and the finished task is not sent again.
