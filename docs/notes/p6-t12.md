### How the service starts

`uvicorn --factory flow.service:create_service_app --host 0.0.0.0 --port $PORT` (Render sets `PORT`, default 10000).

1. **Lifespan start (synchronous).** `load_config` reads the environment. A missing variable raises `RuntimeError("missing required environment variables: A, B")` and uvicorn exits; the message holds names only. A database URL without TLS is refused by `FlowSettings.from_env` (T11), also without echoing the URL. Required: `ARGUS_FLOW_DATABASE_URL`, `GITHUB_WEBHOOK_SECRET`, `GITHUB_DISPATCH_TOKEN`, `ARGUS_FLOW_REPO`, and `GITHUB_TOKEN` unless `ARGUS_FLOW_POLL_ENABLED` is `0`, `false`, `no` or `off`.
2. **Port opens.** `/health` answers `200 {"status":"ok","engine":"starting"}` from now on without touching the database.
3. **Background task, the engine.** Wakes the database (`wait_for_database`, bounded, up to about 60 s), launches DBOS (`argus-flow-1`, executor `argus-flow-0`, no conductor key; `flow.dbos_runtime.launch`), builds the three `ActionsRunner`s and the poller, then runs `poll_forever`. `/health` turns to `"engine":"ready"`. If the engine cannot start, `/health` is `503 {"status":"error","engine":"failed"}`, so Render's health check restarts the instance after 60 s (health-checks page, read 2026-11-01); the log line is `workflow engine did not start (<ExceptionClass>)`.
4. **A webhook during step 3** is answered 202 as always; its background enqueue waits up to 120 s for the engine, then enqueues. If the engine never comes, the enqueue raises, the webhook forgets the delivery id and logs, and the poller or a redelivery repairs it (T06).
5. **Shutdown.** The poll loop ends at its next wake-up (a poll in progress finishes first), then `DBOS.destroy()`.

Routes: `POST /webhook` (T05/T06, review-comment QA path T10 mounted with `send_review_signal`), `GET /health`, `GET /health/db` (opens one connection and runs `select 1`; 200 `{"database":"ok"}` or 503; it wakes a suspended Neon compute and counts toward CU-hours, so do not use it as Render's health check).

### Build and start choice: native Python, no Dockerfile

One line why: the repo is a uv workspace with a root `uv.lock` and `.python-version` (3.12), and Render's docs say it adds uv to a Python service when `uv.lock` is in the root and reads `.python-version`, so a Dockerfile would only copy the whole workspace into an image to run the same two commands.

- Build: `uv sync --frozen --package flow --no-dev`
- Start: `uv run --frozen --no-sync --package flow uvicorn --factory flow.service:create_service_app --host 0.0.0.0 --port $PORT`
- `uvicorn` is not a declared dependency of `flow`: it is locked (0.54.0) because `mcp==2.3.0`, which `flow` depends on, requires it. I changed neither `pyproject.toml` nor `uv.lock`. If `mcp` ever drops it, the start command fails with "command not found"; adding `uvicorn` to `packages/flow/pyproject.toml` is the fix.
- Facts read from Render docs on 2026-11-01 (by a fetch agent, not by hand): blueprint keys `runtime`, `plan: free`, `buildCommand`, `startCommand`, `healthCheckPath`, `autoDeployTrigger` (replaces `autoDeploy`); `PORT` default 10000 on `0.0.0.0`; `.python-version` may omit the patch; uv is added when `uv.lock` is in the root; a failed health check for 15 s stops routing and for 60 s restarts the instance.
- **Not confirmed from the docs:** the exact shape of an `envVars` entry (I used `key` plus `sync: false` / `value`, from memory); that `healthCheckPath` is honoured on the free plan (the page does not say); whether `uv sync` in the build step leaves `.venv` where `uv run` in the start step finds it on Render's build/run split; the build command Render expects for uv (the pages give none). The first deploy decides these three; if the start step cannot find the environment, change the start command to run `uv sync` first (slower cold start).

`render.yaml` has no `branch` and no `repo`: Render takes the repository you connect, and you choose the branch when you apply the Blueprint. `autoDeployTrigger` is `"off"`, so a push does not redeploy; use Manual Deploy. `region` is left at Render's default (`oregon`); pick the Neon region near it.

## Owner steps

I could not do any of these. The console wording is from memory.

1. **Neon first**, if not done: follow steps 1 to 2 of [p6-t11.md](p6-t11.md) section 4. You need the direct (not pooled) URL with `sslmode=require`.
2. **Render account.** Sign up at render.com (a card may be asked for; the free web service does not need a paid plan). Check the free allowances in [p6-t00-versions.md](p6-t00-versions.md): 750 instance hours a month, sleep after 15 minutes idle, cold start "about one minute".
3. **Connect the repository.** Dashboard, New, Blueprint, connect your GitHub account and pick the repository. Choose the branch that contains `render.yaml` and `packages/flow` (today that is the integration branch, `stack/p6-flow`, once it is pushed; I did not push anything).
4. **Apply the Blueprint.** Render lists the service `argus-flow` and asks for each variable marked `sync: false`. Fill in:

   | Variable | Value |
   |---|---|
   | `ARGUS_FLOW_DATABASE_URL` | the Neon direct URL (secret) |
   | `GITHUB_WEBHOOK_SECRET` | a long random string you make up; keep a copy for step 7 (secret) |
   | `GITHUB_DISPATCH_TOKEN` | fine-grained token, Actions read/write on the one repository ([p6-t04.md](p6-t04.md)) (secret) |
   | `GITHUB_TOKEN` | fine-grained token, read-only on issues, pull requests, contents, actions of that repository (secret). Only used when polling is on |
   | `ARGUS_FLOW_REPO` | `owner/name` |
   | `ARGUS_FLOW_QA_REVIEWERS` | comma separated GitHub logins that may approve; leave empty to allow nobody |
   | `ARGUS_FLOW_QA_TIMEOUT_SECONDS` | how long a reviewer may take, in seconds. If it is left empty the code falls back to 60 s, which is for tests |

   `ARGUS_FLOW_POLL_ENABLED` is already `false` in the Blueprint (see "What is stubbed"). Do **not** add `DBOS_CONDUCTOR_KEY`, `DBOS__CONDUCTOR_KEY`, `DBOS__CLOUD`, `DBOS__VMID`, `DBOS__APPVERSION`.
5. **Wait for the deploy**, then open the service's Logs. Expect, in this order: `Initializing DBOS system database with URL: postgresql://...:***@...`, `Application version: argus-flow-1`, `Executor ID: argus-flow-0`, `DBOS launched!`, `workflow engine started; poll loop off`. A line `database not ready, attempt N of 6` means the Neon wake-up probe is working. `workflow engine did not start (...)` means the engine failed and `/health` is 503.
6. **Check `/health` on the public URL.** The URL is shown at the top of the service page (`https://<name>.onrender.com`; I do not know the name Render will give). From any terminal:

   ```bash
   curl -s -m 70 -w ' HTTP %{http_code} in %{time_total}s\n' https://<your-service>.onrender.com/health
   ```

   Expected once the engine is up: `{"status":"ok","engine":"ready"} HTTP 200`. Only when this answers on the public URL may P6-T12 be ticked in `TASKS.md`. If the service was asleep, the time printed is the cold start (T13 measures it properly). Optional: `.../health/db` should give `{"database":"ok"}`.
7. **GitHub webhook.** Repository, Settings, Webhooks, Add webhook: Payload URL `https://<your-service>.onrender.com/webhook`; Content type **`application/json`** (the HMAC is over the raw JSON body; the form encoding would not verify); Secret the same string as `GITHUB_WEBHOOK_SECRET`; events: Issues, Pull requests, Pull request reviews, Pull request review comments. Then Recent Deliveries on that page shows each delivery and its response (a first `ping` is answered `202` with `"status":"ignored"`, a wrong secret `401`).
   **Hold this step until the stubbed client below is replaced**, or accept that every issue event starts a workflow that fails at the PR step.
8. **Poll loop (later).** To turn it on set `ARGUS_FLOW_POLL_ENABLED` to `true` (and `ARGUS_FLOW_TICKET_LABEL` to a label so only labelled issues are polled). It runs only while the instance is awake, and a poll more often than every 5 minutes keeps the Neon compute awake (T14 measures this).

## What is stubbed (exactly)

- **The workflow's GitHub write client is `UnwiredGitHub`.** `push_branch`, `find_pr`, `create_draft_pr`, `ready_pr`, `close_pr`, `post_comment` and `set_label` each raise `NotImplementedError`. No real implementation of the `GitHubClient` protocol exists in the repo (only `FakeGitHub` in tests; `HttpGitHubReader` is read-only and has a different shape; T04 built the runners only). I did not write one: it is a separate piece of work with its own tests and was not in this task. Effect for a real ticket: repro, fix and verify would dispatch to GitHub Actions through the real `ActionsRunner`, then `open_pr_step` fails three times, the ticket ends in `failed`, and the `failed` step's own comment and label calls raise, so the workflow ends in DBOS `ERROR`. Nothing is written to GitHub by the service.
- **`agent-job.yml` has never run and `flow.agent_job` does not exist** (T04), so a dispatched run fails in any case.
- **The MCP QA tool (`flow.qa_mcp`) is not mounted.** QA approval works through the review-comment path only.
- **The dispatch ref is `main`** (the `ActionsRunner` default); there is no environment variable for it.
- Because of the first two points the Blueprint sets `ARGUS_FLOW_POLL_ENABLED=false`: with polling on and no label, the poller would enqueue a workflow for every open issue of the repository.

## What was verified locally

Date 2026-11-01, Windows, Python 3.12, uvicorn 0.54.0 from `uv.lock`.

- `uv run --all-packages python -m pytest packages/flow/tests -q` without a database: 298 passed, 37 skipped (the skips are the tests that need a Postgres or a container). `test_service.py` covers: `/health` 200 while the engine start is blocked (no database involved); 503 when the start fails and the log holds the exception class but not the password in the exception text; refusing to start without `GITHUB_WEBHOOK_SECRET` and `GITHUB_DISPATCH_TOKEN`, naming the variables and none of the values; refusing a remote URL without TLS without echoing it; the poll loop runs, survives a failing poll, and stops with no further poll after shutdown; the webhook is mounted, answers 401 to a bad or missing signature and 202 to a good one; a webhook during start-up is enqueued once the engine is ready; `render.yaml` parses, is a free web service with `/health`, has the four secrets as keys with no value and no conductor or `DBOS*` variable.
- **The service run locally with uvicorn and curl** (the database address is a dummy that does not answer, to show that `/health` does not need it; all values are placeholders):

  ```bash
  export ARGUS_FLOW_DATABASE_URL='postgresql://postgres:dummy-pw@127.0.0.1:55439/none' GITHUB_WEBHOOK_SECRET=dummy-hook GITHUB_DISPATCH_TOKEN=dummy-dispatch GITHUB_TOKEN=dummy-read ARGUS_FLOW_REPO=acme/shop ARGUS_FLOW_POLL_ENABLED=false PORT=8123
  uv run --frozen --no-sync --package flow uvicorn --factory flow.service:create_service_app --host 127.0.0.1 --port $PORT
  curl -s -w ' HTTP %{http_code} in %{time_total}s\n' http://127.0.0.1:8123/health
  ```

  Real output: `{"status":"ok","engine":"starting"} HTTP 200 in 0.004156s` (about 4 ms, warm local process); `POST /webhook` without a signature: `{"detail":"invalid signature"} HTTP 401`. The log then showed `database not ready, attempt 5 of 6 (ConnectionTimeout); retrying in 15.0 s`, and after about 70 s `database did not answer after 6 attempts (ConnectionTimeout)` and `workflow engine did not start (DatabaseUnavailable)`, and `/health` turned to `{"status":"error","engine":"failed"} HTTP 503`. Searching the uvicorn log for the placeholder secrets found 0 matches. That 4 ms says nothing about Render's cold start.
- **Not run: the whole service against a real Postgres.** `test_the_whole_service_starts_against_a_real_postgres_and_stops` (skipped without `ARGUS_FLOW_DATABASE_URL`) needs a database. I created my own container `argus-p6-pg-w4b` (postgres:16-alpine, `127.0.0.1:55439`, password generated into a temporary file outside the repo); then the Docker Desktop engine stopped answering (`docker ps` printed nothing within 40 s; an earlier call returned HTTP 500 from the engine pipe) and connections to port 55439 timed out.
