# P5-T09 Backend swap: Phoenix, run locally

Run on 2026-11-01. The same stubbed fix-loop run (the stub of `packages/fix-loop/tests/test_otel_spans.py`: two model calls, tools `read_file` and `submit`) was sent to a local Phoenix. The only settings that changed were the exporter endpoint and the normalizer profile. Langfuse was not part of this check (no account, see `p5-t07.md`).

## What was installed

- **I installed `arize-phoenix` 21.0.0** (PyPI, Elastic-2.0) with `uv pip install` into a throwaway virtualenv on Python 3.12.10 at `%TEMP%\phx-venv`, outside the repo. It is not in the uv workspace and not in `uv.lock`. Delete the folder to remove it.
- It did not install at first: the network was down for about 25 minutes (PyPI and every other host unreachable), and a second attempt failed because the scratchpad path was too long for Windows. The short path above worked.
- On this machine Windows Application Control blocks pandas' native DLL, so `import phoenix` and the `phoenix serve` command fail with `DLL load failed while importing parsers`. The server itself starts with `python -m phoenix.server.main serve` (it does not load that DLL). Nothing here used the Phoenix Python client.

## The two runs

```bash
# Phoenix, started from the throwaway venv; UI http://127.0.0.1:6006, OTLP/HTTP http://127.0.0.1:6006/v1/traces
PHOENIX_WORKING_DIR=$TEMP/phx-work $TEMP/phx-venv/Scripts/python.exe -m phoenix.server.main serve

# run 1: profile phoenix
ARGUS_TRACE_BACKEND=otlp OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://127.0.0.1:6006/v1/traces ARGUS_TRACE_PROFILE=phoenix \
  uv run --package fix-loop --with jsonschema python stub_run.py phx-run-1      # stop_reason: submit, unmapped: {}

# run 2 (control): same endpoint, profile none
ARGUS_TRACE_BACKEND=otlp OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://127.0.0.1:6006/v1/traces ARGUS_TRACE_PROFILE=none \
  uv run --package fix-loop --with jsonschema python stub_run.py phx-run-none
```

`stub_run.py` is the test stub with `start_tracing()` called with no argument, so the environment picks the exporter. It lives in the session scratchpad, not in the repo. The committed equivalent is `packages/fix-loop/tests/test_backend_swap.py` (below).

## What the control run showed (not what I expected)

Phoenix 21 already reads the GenAI names itself. With profile `none` it still gave the right kinds (AGENT, LLM, TOOL), `llm.model_name`, `llm.token_count.prompt/completion/prompt_details.cache_read`, and even a computed `llm.token_count.total=107`, and it kept the `gen_ai.*` names beside them. So for Phoenix 21 the profile is **not required for the trace to show up and be typed correctly**. What the profile added in this run:

- `llm.cost.total` (cost). Without it the argus cost, which is `argus.usage.cost_usd`, is not under a name Phoenix reads. The page still showed a cumulative cost below $0.01 for both runs, so Phoenix computes some cost on its own from the model name; I did not compare the two numbers.
- `agent.name` and `tool.name` as OpenInference names.
- What it cost: the profile moves the `gen_ai.usage.*` names away, and in run 1 Phoenix did **not** derive `llm.token_count.total` (run 2 has it). A small loss. Fix if wanted: keep the three `gen_ai.usage.*` token names in the Phoenix profile (copy instead of move), or add the total in the profile.

This was seen on Phoenix 21.0.0 only. Older Phoenix versions may need the profile more.

## Test in the repo (no Phoenix needed)

`packages/fix-loop/tests/test_backend_swap.py` runs the same stub twice against two local HTTP servers that decode the OTLP protobuf: once with the `langfuse` backend (path `/api/public/otel/v1/traces`, profile `langfuse`), once with `otlp` pointed at `/v1/traces` and profile `phoenix`. It checks the same five spans reach both, each with its profile's names, and that `unmapped_attributes()` is empty. It shows what argus sends; it does not show that Langfuse or Phoenix accept it (the Phoenix run above is the evidence for Phoenix).

Proof: `uv run --package fix-loop --with jsonschema pytest packages/fix-loop/tests/test_backend_swap.py -q`
