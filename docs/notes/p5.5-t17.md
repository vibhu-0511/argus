# P5.5-T17 package README and phase report

Docs plus one small code change. No model call, no new run. Every number below comes from the stored `verdict.json` and `fix/trajectory.jsonl` files through the repo's own tools.

## What was made

- `packages/skills/README.md`: what the package is, the 5 skills (archetype, source runs, tools, loads in T08), the loader behaviour from `fix_loop.skills`, the commands.
- Two results files in the repo's results JSON schema, one for each T08 row, made from the stored runs:

  ```
  uv run --all-packages python -m eval.ablation tasks --out <tasks.json>          # the 29 runnable seeded tasks
  uv run --all-packages python -m eval run --tasks <tasks.json> --agent packages/eval/results/t08/without-skills.agent.json --out packages/eval/results/t08/without-skills.json
  uv run --all-packages python -m eval run --tasks <tasks.json> --agent packages/eval/results/t08/with-skills.agent.json    --out packages/eval/results/t08/with-skills.json
  ```

  The agent configs use the existing `eval.t14_turn:replay` factory, which reads finished runs and calls no model. Row without skills reads `packages/eval/results/t14/A` (the stored P5-T14 variant A); row with skills reads `packages/eval/results/t08/S`. The resolved counts printed by the run (`19/27`, `21/29`) are the T08 numbers; no figure was typed by hand.
- One code change: `replay` in `packages/eval/src/eval/t14_turn.py` takes `params.fix_only`. The stored variant A runs also have a repro stage (83 steps) that never reached the fix prompt; variant S has none. With `fix_only` the totals of both rows are the fix stage, as in T08. A test (`test_replay_fix_only_leaves_the_repro_stage_out_of_the_totals`) covers it. The default is unchanged.
- `phases/P05.5-argus-skills.md`: the ablation table and the phase report filled from the two results files.
- `docs/architecture/overview.md`: the P5.5 part is final (all components and links).
- `docs/notes/p5.5-pr-body.md`: a draft of the pull request description.

## Phase report

Generated with `python -m eval report <previous> <this>`:

| Previous phase (P5, `ablation-B.json`) | 71.4% (20/28) | 34,940 | $0.0694 | 1617.0 s | 5097.5 s |
| This phase (`t08/with-skills.json`) | 72.4% (21/29) | 40,400 | $0.0824 | 1106.5 s | 2361.0 s |
| Delta | +1.0 pp | +5,460 (+15.6%) | +$0.0130 (+18.7%) | -510.5 s | -2736.6 s |

- **Previous phase** is P5's own result: the routed pipeline (variant B, repro on the cheap tier, fix on the strong tier), the row P5's report used as "this phase". The file is the stored `packages/eval/results/ablation-B.json`; it was not remade.
- **This phase** is the fix stage with the 5 skills loaded (variant S).
- **The delta is not a clean comparison** and the phase file says so: B ran a repro stage and routing, S ran the fix stage only, on different days. Tokens, dollars and latency do not compare. The resolve-rate delta (+1.0 pp, 20/28 against 21/29) is inside both Wilson intervals and means no change.

The comparison that isolates the skills (same policy, same fix stage, same tasks):

| Report | Resolve rate | Tokens/bug | $-equivalent | p50 latency | p95 latency |
|---|---|---|---|---|---|
| Without skills (`t08/without-skills.json`) | 70.4% (19/27) | 37,624 | $0.0769 | 819.0 s | 1800.7 s |
| With skills (`t08/with-skills.json`) | 72.4% (21/29) | 40,400 | $0.0824 | 1106.5 s | 2361.0 s |

- The +2.0 pp comes from the two tasks (`seed-h06`, `seed-h09`) that the scorer could not score in the without row (exit 2). On the 27 tasks scored in both rows the outcome is the same on every task: 19 resolved in both, 8 in neither (`eval.skills_ablation`).
- Tokens/bug is in plus out per scored task: 37,419 + 205 and 40,199 + 201. On the 27 paired tasks only, tokens in are 37,419 against 40,470 (+8%), the figure in T08.
- Skills loaded: 14 of 29 runs loaded one skill each, 15 loaded none; 12 loads of `css-value-changed-in-existing-rule`, 2 of `css-rule-missing-for-class`, none of the other three.
- Latency is not comparable: the rows are a day apart, three coordinators ran at once on a shared machine, and the wall clock includes coordinator waits. The results file leaves the excluded runs out of the percentiles (without skills 819 s and 1,801 s); `docs/notes/p5.5-t08.md` quotes 992 s and 1,830 s because `eval.skills_ablation` includes the two excluded runs in its latency. Neither is a measurement of the skills.
