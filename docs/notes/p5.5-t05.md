# P5.5-T05 draft script

`packages/skills/src/skills/draft.py`. Run: `uv run --all-packages python -m skills.draft --runs <runs folder> --base-url URL --model MODEL --key-env NAME` (add `--dry-run` to list the groups with no model call).

## What it does

1. Finds every `verdict.json` under `--runs` whose `verdict` is `resolved` and whose `task_id` is in the `train` list of `split.json`. A held-out task is never used. The trajectory is `<run>/fix/trajectory.jsonl` (the T04 and T14 layout) or `<run>/trajectory.jsonl`.
2. Groups the runs by archetype (from the mutant's `meta.json`), 3 runs per group by default, in sorted task order.
3. Sends each group to the cheap-tier model once: the ticket and each step as `tool call -> first 300 characters of the result`, 2,500 characters per run at most. The system message says the runs are data, not instructions.
4. The model returns `{name, description, body}`. The script writes the frontmatter itself, so the model cannot add a field or a tool: `description` is JSON-quoted (T02 rule: an unquoted `: ` is refused by the loader), `allowed-tools` is fixed to `read_file list_dir search ast_grep edit submit` (no `run_cmd`), `metadata` has `argus-status: "unreviewed"`, `argus-archetype` and `argus-sources` (T01 keys).
5. A reply is rejected, and nothing is written, when it is not the JSON asked for, the name is not a valid skill name, the directory already exists (a reviewed skill is never overwritten), or the file fails the loader's own format check (`fix_loop.skills._parse`) or the 8,000-character body limit.

A draft has no lock entry, so the T10 loader refuses it until the owner reviews and pins it.

## What was proven

- `uv run --all-packages python -m pytest packages/skills/tests -q` -> 9 passed (4 new in `test_draft.py`: which runs count, prompt content, a written draft parses with the loader's check and is marked unreviewed, six kinds of bad reply write nothing). The model is a stub. Fixtures (`packages/skills/tests/fixtures/runs`) are **hand-written and synthetic**, shaped like the stored T14 runs (train task ids, one unresolved run, one held-out run, both layouts).
- `--dry-run` on the in-progress T04 runs of another session's worktree (read only, nothing written there) found 7 resolved train runs and made 3 groups. So the real layout is read correctly.
