# P5-T19 SWE-bench Multimodal subset adapter

## Sources (read 2026-11-01)

- Dataset card: `https://huggingface.co/datasets/princeton-nlp/SWE-bench_Multimodal` (README). Dataset id `princeton-nlp/SWE-bench_Multimodal`. Splits: `dev` 102 rows, `test` 510 rows. The card text says 617 instances; the paper ([arXiv 2410.03859](https://arxiv.org/abs/2410.03859)) says 619 and the swebench.com loading guide says 100 dev / 500 test. Our count is from the card metadata and the rows API: dev = 102.
- Fields (card): `repo`, `instance_id`, `base_commit`, `patch`, `test_patch`, `problem_statement`, `hints_text`, `created_at`, `image_assets`, `version`, `FAIL_TO_PASS`, `PASS_TO_PASS`. All strings. `image_assets` is a JSON string with the keys `problem_statement` (list of image URLs), `patch` and `test_patch` (lists of `{path, url}`).
- The swebench.com guide says the `test` split has empty `patch`, `test_patch` and `image_assets` (evaluation is private). That is why the adapter pins `dev`.

## What was fetched

Only the `dev` split, with plain HTTP GETs to `https://datasets-server.huggingface.co/rows?dataset=princeton-nlp/SWE-bench_Multimodal&config=default&split=dev&offset=N&length=10` (plus one probe of `/splits`). The 102 rows came to 4.3 MB of JSON, including gold patches; the server answered 502/503 on some pages and the fetch retried. The raw file was kept outside the repo. `test` was not fetched. The user allowed this fetch in the task brief.

## Why not an `argus_core.types.Task`

`Task` needs a `bug_patch`, a `golden_patch` and Playwright checks (`pixel_diff`, `bounding_box`, `computed_style`) on the Canvas app. A SWE-bench row has no bug patch (the bug is the base commit) and is scored by repo test names (`FAIL_TO_PASS`) after applying a hidden `test_patch`. Forcing it into `Task` would mean inventing checks. So the adapter returns `MultimodalTask`: an id, repo, base commit, version, an argus `Ticket` (text = `problem_statement`, no local screenshot yet), `image_urls`, and `fail_to_pass`. It has no patch field, so the gold patch cannot reach the prompt by construction. `build_prompt` is the only prompt builder. Images are URLs; T20 decides how to download and attach them.

## Rules

- Split pinned to `dev`. A row whose `split` is not `dev` gets an exclusion `wrong-split` (tested with synthetic test rows; the committed file lists dev rows only because the test split was not fetched).
- `missing-image-assets`: `image_assets` empty, not JSON, `problem_statement` URL list empty, or a non-http URL. 7 dev rows, all `chartjs/Chart.js` (their images are only in the `test_patch`, so the agent would see no screenshot): 9764, 9766, 10806, 7951, 9199, 9678, 8868.
- `statement-quotes-gold-patch`: the issue text contains the whole gold patch or an added line of 25+ characters from it. 4 rows, all `processing/p5.js`: 5917, 5970, 5915, 6069. Without this the prompt would contain the fix.
- `hints_text` (issue comments) is dropped from the prompt: it can quote the fix (5 dev rows had a gold line in it).
- Selection from the 91 eligible rows: sorted by `(repo, instance_id)`, at most 3 per repo, gold patch at most 4000 characters. 15 tasks selected across 5 repos. 76 eligible rows are listed as `not-selected` with the reason. Small patches also make the committed leak-test file small. This biases the subset toward small fixes; say so when reporting T20 results.

## Files

- `packages/eval/data/multimodal/subset.json` (46 KB): the subset list and, for the 15 rows, every dataset field except `patch`, `test_patch` and `PASS_TO_PASS`. `PASS_TO_PASS` is up to 170 KB per p5.js row; the T20 scorer reads it from the dataset.
- `packages/eval/data/multimodal/excluded.json`: all 87 non-selected dev rows with reason and detail.
- `packages/eval/data/multimodal/gold_patches.json` (23 KB): gold patches of the 15 selected rows. This goes beyond "non-patch fields"; it exists only so the offline test can check that no gold text appears in any prompt. Nothing in `eval` reads it except that test.
- Rebuild: `python -m eval multimodal fetch --out raw.json` then `python -m eval multimodal build --raw raw.json`.

## Limits

- The leak check is textual (whole patch or a 25+ character added line). One selected patch (`processing__p5.js-5555`) adds only short lines, so only the whole-patch check applies to it; the test caps such patches at 2.
- Not run: the model run on these tasks (T20), image download, and scoring (needs the SWE-bench harness, repo checkouts and `PASS_TO_PASS`).
