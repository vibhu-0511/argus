## What is automated

One command replays a finished stored run as a trace and checks it arrived:

```powershell
uv run --all-packages python -m eval.trace_replay packages/eval/results/t14/B/seed-e01
```

1. **Replay** (`packages/eval/src/eval/trace_replay.py`). Reads `repro/trajectory.jsonl`, `fix/trajectory.jsonl` and `verdict.json` of the run folder (`answers.jsonl` is not needed: reply text stays off spans). For the example run that is 16 spans: root `invoke_agent argus-run`, `invoke_agent repro-agent` and `invoke_agent fix-loop`, 8 `chat` spans (model, tier, stage, token counts, `argus.usage.cost_usd`, stop reason) and 5 `execute_tool` spans (fix stage). A failed tool gets error status and `error.type`; a reply that was not a tool call (`not-a-repro`) only gets `argus.tool.error` on its `chat` span, with no error status.
2. **Marked as a replay.** Every span has `argus.replay=true` and `argus.replay.source_run=<run id>`. The root carries a note on how the times were made. The Langfuse session id is `argus-replay-<run id>` (`--session` overrides it).
3. **Export** through `start_tracing()`: `ARGUS_TRACE_BACKEND`, `LANGFUSE_*` and the profile come from the environment. The command prints `export=SUCCESS` or `export=FAILURE` and exits 1 when the export failed. A missing key with `ARGUS_TRACE_BACKEND=langfuse` exits 2 with the variable names (never values); nothing is sent then.
4. **Check through the API.** With the Langfuse backend, after a successful export it asks Langfuse for the session's observations (waits and retries up to 6 times, 5 seconds apart, because ingestion lags) and writes `docs/notes/p5-t23-trace-evidence.md`: trace id, session, observation names, types, levels, start and end times, counts. No key, no message text. If nothing comes back it says so and writes no file. This check never changes the exit code; with another backend (`console`, `otlp`) it is skipped.
5. The module never reads a key: the Basic header comes ready-made from `trace_config()` and is only sent. A test checks that neither key, nor the Basic string, nor its base64 appears in the output or in the evidence file.

## Things that differ from what was asked, and why

- **Route.** The task named `GET /api/public/traces`. The Langfuse docs (read 2026-11-02, <https://langfuse.com/faq/all/deprecated-api-migration> and <https://langfuse.com/faq/all/api-limits>) say Cloud serves that route only until 2026-11-16, that it returns no trace body shape the docs document, and that Hobby allows 5 requests a minute on it. The command uses `GET /api/public/v2/observations?sessionId=…&fields=core,basic&fromStartTime=…&toStartTime=…` (30 requests a minute on Hobby). The evidence is therefore observations, not a trace object; the trace id is read from `traceId` on the rows.
- **Not confirmed:** the docs read do not show the v2 response body. The code accepts `{"data": [...]}` or a bare list, and reads `id, traceId, name, type, level, startTime, endTime, parentObservationId`. If the first real run shows other names, the evidence file will be thin or empty and the code needs a one-line change. The offline tests use a fake that follows the field-group names in the docs, which proves nothing about the real body.
- **Times are laid out, not recorded.** A trajectory stores no per-step clock. The recorded wall time of the run (`verdict.json`: `started_at` to `finished_at`, 1,083 s for the example) is split evenly across the steps in order (repro first, then fix); a step with a tool call gives 70% to the model call and 30% to the tool. The spans show real order and a plausible shape, not real durations. Say so if anyone quotes a latency from this trace.
- **Dollar figures.** `verdict.json` says `token_source: chars/4 estimate` for this run, so the cost on each `chat` span is a list-price figure on estimated tokens.
- **Finish reasons** are not stored in trajectories, so `gen_ai.response.finish_reasons` is absent (`docs/notes/p5-semconv.md`, note 2).
- **Five new argus attribute names** were added to `KNOWN` and the Langfuse profile in `argus_core/trace_normalize.py`, so the normalizer's unmapped counter stays at zero for a replay: `argus.replay`, `argus.replay.source_run`, `argus.replay.note`, `argus.stage`, `argus.verdict`.
- **Queue.** A replay of more than 512 spans would drop the rest (the batch queue of ADR-015); the command warns. The example run has 16.

## What is not automated

- **The screenshot.** An agent cannot sign in to your Langfuse project, so it cannot take one. The evidence file from the API stands in for it. If you want the T23 row met to the letter, open the trace in Langfuse, take a screenshot that does not show your organisation name or keys, and commit it (for example `docs/notes/p5-t23-trace.png`).
- **The dashboard link.** There is no public dashboard URL: GitHub Pages is not available on this private repo (`docs/notes/p5-t22.md`). The README says how to open the page from disk or from the workflow's `dashboard` download.
- **A live run's trace.** Nothing in the real fix-loop or repro run starts tracing on its own; a loop still has to call `start_tracing()`. This task shows a replay of a stored run, which is labelled as such everywhere.
- **Hobby retention** is 30 days: the trace the README points to expires after that.

