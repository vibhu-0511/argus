# P8 architecture

Source: `phases/P08-argus-app.md`. P8 packages Argus as a GitHub App. Each tenant runs a reusable workflow in their own repo, with per-tenant quota budgets, ticket intake, PR creation with evidence, a backport bot, and a single-agent vs planner ablation. This file grows by one section per task. After each wave the orchestrating session folds the sections into the diagram in `overview.md`.

P8 was started with P6 still open (draft PR #12) and with the dependency of `P8-T04` on `P6-T04` waived; see `docs/notes/p8-waves.md`.

## P8-T02 Create the GitHub App manifest

- New components: `argus_app.manifest` (loader, validator, local registration page, `run`), `argus_app/manifest.json`, the `argus-app manifest [--form]` sub-command in `argus_app.cli`.
- Links to existing parts: the permission list is `flow.app_token.MINIMUM` (P7-T04), which `manifest.py` imports and compares with `default_permissions`; the test also parses the table in ADR-026. The webhook URL is `<ARGUS_FLOW_SERVICE_URL>/webhook`, the route of the P6 flow service (`flow.webhook`); the events are the ones that service handles. No URL is committed: the service URL, the App homepage and the redirect URL come from environment variables.
- Files: `packages/app/src/argus_app/manifest.json`, `manifest.py`, `cli.py`; `packages/app/tests/test_manifest.py`; `docs/notes/p8-t02-owner-steps.md`.
