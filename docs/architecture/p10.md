# P10 architecture

Source: `phases/P10-argus-workbench.md`. P10 is a local web UI (`packages/workbench`, module `argus_workbench`, command `argus-workbench serve`) with five screens over scripted and replayed runs. It binds 127.0.0.1, has no login and calls no model. Every run it makes is tagged SIMULATED or REPLAY and is in no aggregate. This file grows by one section per task. The diagram in `overview.md` is changed only by the integrator.

## Architecture agreements

Groups follow these names. A group extends them only by adding files (a `routes/<name>.py`, a `static/screens/<name>.js`, a new test file), not by editing the files of another group.

### Modules

| Module | What it is for | Names other groups use |
|---|---|---|
| `store.py` | the run store and the run record | `create_run`, `read_file`, `write_file`, `has_file`, `get_state`, `advance`, `list_runs`, `check_run_id`, `run_dir`, `store_root`, `display_state`, `new_run_id`, models `RunState`, `Verdict`, `Check`, `Decision`, `PrFile`, `Intake`, constants `FILES`, `RUN_ID`, `ENV_ROOT` |
| `errors.py` | the typed error | `WorkbenchError(code, message, field=None, status=400)`, `from_validation` |
| `spec.py` | the packaged design spec | `load_spec()`, `tabs()`, `scenario_ids()`, `P10_STATUS` |
| `fixtures.py` | example run folders, all SIMULATED | `write_fixture_run(scenario, ...)`, `write_all_fixtures(...)`, `fixed_clock()` |
| `cli.py` | `argus-workbench serve [--port N]` | `main(argv)` |
| `server.py` | `create_app(token=None)`; includes every module in `routes/` that has a module-level `router` (found by `pkgutil`, sorted by module name) | `create_app`, `include_route_modules` |
| `security.py` | Host and Origin allow-list, per-start token, CSP and other headers | `TOKEN_HEADER`, `CSP`, `REPORT_CSP`, `mask`, `new_token` |
| `static/` | `index.html`, `app.js` (tab router), `api.js`, `dom.js`, `style.css`, `screens/<screen>.js` | see "Page shell" below |

A group that adds an API adds `routes/<name>.py` with `router = APIRouter()`. It needs no token code: the middleware refuses a POST, PUT, PATCH or DELETE without the token before the route runs. Routes read and write runs only through `store`. Test with `TestClient(create_app(token="test-token-not-secret"), base_url="http://127.0.0.1")` and `monkeypatch.setenv("ARGUS_WORKBENCH_RUNS", str(tmp_path))`, and send the token as the `X-Workbench-Token` header.

### Run lifecycle

1. Create: `store.create_run` writes `ticket.json` and `state.json` in state `received` (T03 does this from the form; it also writes `intake.json`).
2. Start: `POST /api/runs/{id}/start` hands the run to the runner manager (T04). It plays the run in a background thread with an injectable tick (tests use 0 ms, the UI uses 700 ms, the spec's `sim.tick_ms`). Each state change goes through `store.advance`, which only allows the transitions of `flow.states.TRANSITIONS`.
3. Watch: the page polls `GET /api/runs/{id}` (T06). Polling, not SSE.
4. Review and decide (T07), then the PR (T08).
5. History (T09) reads `store.list_runs` and the run files.

Retry and Request changes create a NEW run folder in state `received` with `created_by_retry_of` set. The old folder is never changed (`create_run` only reads it to check that it exists; a test compares the bytes).

### States

State names are `flow.states.State` values: `received`, `reproducing`, `fixing`, `verifying`, `opening-pr`, `awaiting-qa`, `done`, `failed`, `rejected`, `timed-out`. `quota-wait` and `stuck` are display states, derived in `state.json` field `display_state` from `stop_reason` (`QuotaExceeded` gives `quota-wait`, `stuck` gives `stuck`, anything else gives the state name). They are never a stored state. The spec's own list (`workflowStates`) was marked PROPOSED and is not used.

Stage to flow state: reproduce is `reproducing`; locate and fix are both `fixing` (flow has no locating state); verify is `verifying`.

| Scenario | Ends in state | Stop reason | Display state | Verdict file |
|---|---|---|---|---|
| `normal` | `awaiting-qa` | `submit` | `awaiting-qa` | four checks pass, judge `pass` |
| `quota` | `failed` | `QuotaExceeded` | `quota-wait` | none |
| `stuck` | `failed` | `stuck` | `stuck` | none |
| `verifier` | `failed` (event `verify_failed`, reached from `verifying`) | `submit` | `failed` | overflow fails on a second route, judge `not run` |
| `judge` | `awaiting-qa` | `submit` | `awaiting-qa` | four checks pass, judge `fail` (advisory) |

Path of a normal run through `flow.states`: `received` -start-> `reproducing` -repro_ok-> `fixing` -fix_ok-> `verifying` -verify_ok-> `opening-pr` -pr_opened-> `awaiting-qa`. `quota` and `stuck` leave `fixing` with `fix_failed`.

### API errors

Every JSON error has one shape: `{"error": {"code": "<snake_case>", "field": "<name or null>", "message": "..."}}`. The class is `errors.WorkbenchError`; unknown routes (404), wrong methods (405) and framework validation errors (422, code `invalid_request`) use the same shape. Codes used so far: `bad_run_id`, `unknown_run`, `run_exists`, `unknown_state`, `unknown_stop_reason`, `bad_origin`, `invalid_<file>` (for example `invalid_ticket`, `invalid_verdict`, `invalid_trajectory`), `unknown_file`, `missing_file`, `already_written`, `file_too_large`, `illegal_transition`, `host_not_allowed`, `origin_not_allowed`, `token_required`, `not_found`, `method_not_allowed`, `invalid_request`.

### Run store root

Env `ARGUS_WORKBENCH_RUNS`; default `.local/workbench/runs` under the repo root (`.local/` is git-ignored). Tests always point it at `tmp_path`.

### Page shell

- `GET /` serves `static/index.html` with the per-start token in `<meta name="argus-token">`. `GET /static/*` serves the packaged `static/` folder. `GET /api/tabs` returns the five tabs (`id`, `n`, `title`, `short`, `purpose`, `label`, `level`, `detail`, `status`); `label` is the spec's `screens[].built.label` verbatim and `status` is the P10 line `local, scripted`.
- `static/app.js` is the tab router. The hash is `#/<tab>` or `#/<tab>/<run id>`. It loads `static/screens/<tab>.js`, an ES module that exports `async function render(root, ctx)`; `ctx` is `{tab, tabs, arg, api, go}`, `arg` is the run id from the hash when it matches `[a-z0-9-]{1,64}` (else null). A screen group replaces its placeholder module and adds files; it does not edit `app.js`.
- `static/dom.js` has `el(tag, attrs, ...children)` and `clear(node)`. Text is set with `textContent` or a text node only; `on*`, `style` and `srcdoc` attributes and `href`/`src` values that are not same-origin paths are refused. `static/api.js` has `api(method, path, body)`: it sends the token in the `X-Workbench-Token` header on every non-GET call and throws an `ApiError` with `code`, `field`, `message` for the typed error body.
- Plain ES modules, no build step, no npm, no CDN, no inline script or style (`tests/test_static.py` scans every script for HTML-string APIs and `eval`).

### Request guards (`security.py`)

| Guard | Rule | Refusal |
|---|---|---|
| Host, every method | `127.0.0.1` or `localhost`, optional port, case-insensitive. Anything else, including `127.0.0.1.evil.example`, `[::1]` and an empty Host | 403 `host_not_allowed` |
| Origin, POST PUT PATCH DELETE | if sent, must be `http://127.0.0.1[:port]` or `http://localhost[:port]` | 403 `origin_not_allowed` |
| Token, POST PUT PATCH DELETE | header `X-Workbench-Token` equals the per-start token (constant-time compare). A token in a URL, body or cookie does not count | 403 `token_required` |
| CORS | none: no `Access-Control-*` header is ever sent | a cross-origin page cannot read a response |
| Headers on every response | `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: no-store` | a route may set its own stricter CSP first (the report uses `security.REPORT_CSP`: `default-src 'none'`, `sandbox`) |

The token is `secrets.token_urlsafe(32)` per `create_app()`, goes to the page in the meta tag, never in a URL, and the CLI prints only its first four characters (`security.mask`). What this does not defend: another program or user on the same machine can read the index and get the token; there is no login (ADR-031, T15).

The report frame: the page shows `report.html` in an `<iframe sandbox>` whose `src` is a same-origin path (allowed by `frame-src 'self'`); the report response carries `REPORT_CSP`, so it can run no script and load nothing.

## Run folder contract

One folder per run: `<root>/<run_id>/`. `run_id` must fully match `[a-z0-9-]{1,64}` and must not be a Windows device name (`con`, `prn`, `aux`, `nul`, `com1` to `com9`, `lpt1` to `lpt9`); the resolved folder must be a direct child of the resolved root. File names are never taken from a caller; only the names below exist, and `store.write_file` / `store.read_file` check each against its schema. A file that was edited by hand and no longer validates is refused on read. Text and JSON are UTF-8; writes are atomic (temp file, then replace).

| File | What | Schema | Written by | Written when |
|---|---|---|---|---|
| `ticket.json` | the typed ticket | `argus_core.types.Ticket`: `id`, `text`, optional `screenshot` (`media_type`, `path` relative to the folder). Unknown keys are refused | T03 (`create_run`) | at create, once |
| `intake.json` | what the person chose besides the text: `repo`, `route`, `ack_public_or_synthetic` (extra keys allowed). Sidecar so the ticket stays valid for `bench validate` | `store.Intake` | T03 | at create |
| `state.json` | run state | `store.RunState`: `run_id`, `state` (a `flow.states.State` value), `stop_reason` (an `argus_core.types.StopReason` value or null), `display_state` (derived, checked on read), `origin` (`SIMULATED` or `REPLAY`), `scenario` (one of `normal`, `quota`, `stuck`, `verifier`, `judge`, or null), `created_by_retry_of` (a run id or null), `created_at`, `updated_at` (time zone required; from an injected clock) | `create_run` (T01), then `advance` (runner, T04; review, T07; PR, T08) | every state change |
| `trajectory.jsonl` | one step per line, first line is meta | `argus_core.types.Trajectory` (`from_jsonl`): per step `index`, `tokens_in`, `tokens_out`, `tokens_cached`, `stop_reason`, `tool_name`, `tool_error`, `message`. The workbench puts `{"stage", "text", "origin"}` in `message` | runner (T04, T05) | during the run |
| `verdict.json` | the checks in verify's order (pixel, overflow, axe, console), the first failure, the judge label and note | `store.Verdict`: `ok`, `checks` (each `name`, `ok`, `hard`, `reason`, `route`; the fields of `verify.checks.CheckResult` plus the route), `first_failure`, `failed_check`, `judge_label` (`pass`, `fail`, `not run`), `judge_note`, `judge_advisory` (true while alpha is uncalibrated), `origin`. Checks are unique and in order; an ok verdict lists all four and all pass; a failed one names the failed check. A check that did not run (the run stops at the first hard failure, as `verify.pipeline.run` does) is absent, not listed as passed | runner (T04) | when the run reaches verify |
| `report.html` | before/after report | text, max 2,000,000 bytes. Shown only in a sandboxed frame, served with `security.REPORT_CSP` | runner (T04) | with the verdict |
| `patch.diff` | the patch | text. An empty file means no PR | runner (T04) | when the fix is submitted |
| `decision.json` | the reviewer's decision | `store.Decision`: `decision` (`approve`, `request-changes`, `reject`), `reason`, `idempotency_key` (1 to 128 characters), `decided_at`. Written with `overwrite=False`: a second write is a typed 409 `already_written` | T07 | once per key |
| `pr.json` | the mock PR | `store.PrFile`: `number`, `url`, `draft` (the fields of `flow.workflow.PullRequest` that `argus_app.pr` returns), `origin`; extra keys allowed (T08 adds title, branch, body, CI state) | T08 | on approve |

Rules for every file:

- A runner writes only files of its own run; every file it writes carries the origin tag (`SIMULATED` or `REPLAY`) in its content (verdict, PR, trajectory messages) or in `state.json`. No file is ever tagged as a real model result.
- Nothing in a run folder is an aggregate input: history (T09) lists SIMULATED and REPLAY runs with a badge and leaves them out of every metric.
- Nothing secret is stored in a run folder.
- A retry or a request for changes writes a new folder; the old one is read only.

## P10-T04 Runner protocol, ScriptedRunner, ReplayRunner, RunManager, run controls

- New components: `runner.py` (the `Runner` protocol, `Playback`, `ScriptedRunner`, `ReplayRunner`, `owner_stop`), `manager.py` (`RunManager`), `routes/runs_control.py` (`POST /api/runs/{id}/start`, `/stop`, `/retry`).
- Links to existing code, nothing copied: the step script and the verdict come from `fixtures._steps` and `fixtures._verdict` (the spec's `sim` block); trajectory steps are `argus_core.types.TrajectoryStep` and are written as a `Trajectory`; the quota scenario is charged through `argus_core.ledger.Ledger` (a temp file, a model named `scripted-sim`, a `tokens_per_day` cap one token above what the steps before the halt use) and the halting step carries the text of the `QuotaExceeded` the ledger raised (no illustrative number); every state change is `store.advance`, so only `flow.states.TRANSITIONS` are possible.
- Runner protocol: `play(run_dir, *, clock, tick, stop) -> RunState`. `tick()` runs after every step (UI: wait `sim.tick_ms` = 700 ms on the stop event; tests: a function that does nothing). `stop` is a `threading.Event`. A runner writes only files of its own run, through `store`.
- Origin tag: `state.json` `origin`; every trajectory step has `message.origin` (the trajectory schema forbids extra step fields, so the tag sits in `message`, next to `message.stage`); `verdict.json` `origin`; `patch.diff` and `report.html` say SIMULATED in their text. A runner refuses a run of the other origin (`bad_origin`).

### Scenario table (what `ScriptedRunner` plays)

| Scenario | Stages played | Steps | Ends in state | Stop reason | Display | Files besides ticket, state, trajectory |
|---|---|---|---|---|---|---|
| `normal` | reproduce, locate, fix, verify (judge step) | the spec's events | `awaiting-qa` (via `opening-pr`) | `submit` | `awaiting-qa` | patch, report, verdict (4 pass, judge `pass`) |
| `quota` | reproduce, locate, fix up to the first fix event | halts at the next fix call, which the ledger refuses | `failed` (event `fix_failed` from `fixing`) | `QuotaExceeded` | `quota-wait` | none |
| `stuck` | reproduce, locate (one call, then the same `locate` call 3 times) | stops on the third repeat | `failed` (event `fix_failed`) | `stuck` | `stuck` | none |
| `verifier` | reproduce, locate, fix; passes through `verifying` | no verify steps | `failed` (event `verify_failed`) | `submit` | `failed` | patch, report, verdict (overflow fails on `/ops/horizon`, console absent, judge `not run`) |
| `judge` | as `normal` | as `normal` | `awaiting-qa` | `submit` | `awaiting-qa` | patch, report, verdict (4 pass, judge `fail`, advisory) |

Order of writes in a good run: `START` when the run begins; `repro_ok` when the first locate step starts; `fix_ok` when the verify stage starts (`patch.diff` and `report.html` are written at that moment); `verdict.json` after the verify steps; then `verify_ok` and `pr_opened` (or `verify_failed`).

### ReplayRunner

`ReplayRunner(source_dir)` validates `source_dir/trajectory.jsonl` (argus-core `Trajectory.from_jsonl`, before it writes anything) and copies the steps one per tick into the run, keeping the recorded tokens, tools and stop reasons, with `message.origin = "REPLAY"`, the stage the step carries (`message.stage`; else the previous stage; `reproduce` at the start) and `meta.host = "replay"`. It re-runs and re-verifies nothing, so it writes no patch, report or verdict and the run ends in `failed` with the stop reason of the last recorded step (a replayed `QuotaExceeded` shows as quota-wait). Over the API, `start` takes `{"replay_from": "<run id>"}`, a run of the store (an id, never a path); the run must have origin `REPLAY`.

### Stop

flow.states has no stop event. A stop on a running run (`reproducing`, `fixing`, `verifying`, `opening-pr`) takes the failure event of the state it is in, so the run ends in `failed`. `stop_reason` stays null, because no argus-core `StopReason` means "stopped by owner". The reason is the last trajectory step: tool `owner-stop`, `tool_error` "stopped by owner", `message.text` the same. A screen shows "stopped by owner" when `state` is `failed`, `stop_reason` is null and the last step is `owner-stop`. A run in `received` or in an end state gets 409 `not_running`. The stop event also wakes the tick wait, so stopping a slow run returns at once. A run nobody is playing (after a server restart) is stopped by the manager directly.

### Retry

`retry` creates a new run (`run-<hex>`) in `received` with `created_by_retry_of` set, the same ticket (and `intake.json`), the same origin and scenario (a body `{"scenario": "<id>"}` picks another one, SIMULATED runs only). It does not start it. Only terminal runs other than `done` can be retried (`not_retryable`, 409). A run with stop reason `QuotaExceeded` is refused with 409 `quota_wait` until the UTC date has changed (the ledger rolls its day on the UTC date), so the button is not the only guard. The old folder is only read; a test compares its bytes before and after.

### API

| Call | Body | Answer | Typed errors |
|---|---|---|---|
| `POST /api/runs/{id}/start` | optional `scenario`, `replay_from` | `{"state": state.json}` (state `reproducing`; the run plays on a daemon thread) | `unknown_run`, `bad_run_id`, `not_startable` (409), `scenario_required`, `unknown_scenario`, `replay_source_required`, `bad_replay_source`, `invalid_trajectory`, `missing_file` |
| `POST /api/runs/{id}/stop` | none | `{"state": ...}` | `not_running` (409) |
| `POST /api/runs/{id}/retry` | optional `scenario` | `{"state": ...}` of the new run | `not_retryable`, `quota_wait`, `unknown_scenario` |

The manager lives on `app.state.run_manager` (created with the 700 ms tick on first use; a test puts `RunManager(tick_ms=0)` there first). If the runner raises, the thread marks the run `failed` (stop reason null) so no run is left running.

## P10-T05 FixLoopRunner adapter (scripted model only)

- New component: `fixloop_runner.py` (`FixLoopRunner`). It follows the `Runner` protocol of `runner.py` and reuses `Playback`, so state changes are `flow.states` transitions and the trajectory goes through `store`.
- Links to existing code: `fix_loop.loop.run_fix` (called with `ledger`, `complete` and `execute`, the way `packages/fix-loop/tests/test_loop.py` does), `fix_loop.tools.call` for the tools, `argus_core.ledger.Ledger` (a temp file with a large cap), `argus_core.types.Trajectory`.
- Never run against a real model. The constructor requires `model`, a plain function (messages in, answer out). There is no default, and no key, URL or model name is read at import or later; no client is built. `run_cmd` and `ast_grep` are refused unless `allow_shell=True`. It is not reachable from the HTTP API (the manager builds only `ScriptedRunner` and `ReplayRunner`); only tests and local scripts construct it.
- Mapping: `run_fix` runs to its end first and writes its trajectory in a temp folder; the steps are then copied into the run one per tick, with `message.stage = "fix"` and `message.origin = "SIMULATED"` added (the fix-loop `text` and `returncode` stay). `patch.diff` is the diff of the worktree (`git diff`) with a `# SIMULATED` first line, and is not written when the diff is empty. The state passes through `reproducing` with no repro step (only the fix stage runs).
- End state: `failed` with the stop reason `run_fix` returned (`submit`, `stuck`, `step-cap`, and so on). It never reaches `awaiting-qa`, because no verify pipeline runs here and no verdict exists. Same rule as `ReplayRunner`: only `ScriptedRunner` writes a verdict.
- Ceiling: a stop is checked between copied steps, not inside `run_fix`.
- Files: `packages/workbench/src/argus_workbench/fixloop_runner.py`, `packages/workbench/tests/test_fixloop_runner.py`, a line in `packages/workbench/README.md`.
- Proof: `uv run --all-packages python -m pytest packages/workbench/tests/test_fixloop_runner.py -q`. A scripted model (read_file, edit, submit) edits a temp repo, and the run folder validates (trajectory schema through `store.read_file`, `state.json`, the diff). A mutated build with the shell guard removed fails `test_a_shell_tool_is_refused_by_default`.

## P10-T06 Screen 2: Live run

- New components: `routes/runs_view.py` (`GET /api/runs/{id}`, read only, no token), `meter.py` (the quota meter), `static/screens/run.js` and `run.css` (the screen; it loads its own stylesheet, so `style.css` and `index.html` are untouched).
- Polling, not SSE: while the view says `poll.again` (the run is reproducing, fixing, verifying or opening-pr) the page asks again after `poll.interval_ms` (the spec's `sim.tick_ms`, 700) and stops when the run is not playing, or when the person leaves the screen. The page is built once and updated in place, so a click is never lost to a redraw.
- Links to existing code, nothing copied: `store.get_state/read_file` (validated on read), `runner.ACTIVE` and `OWNER_STOP_TEXT`, the stage list and the stuck text of the packaged spec, `argus_core.ledger.load_quotas` and the ledger's `QuotaExceeded` message shape.
- View: `run` (state.json), `origin` (tag and note), `stages` (Reproduce, Locate, Fix, Verify: pending, running, done, failed, stopped), `steps` (tool, text, tokens in/out/cached, stop reason, `repeat`), `totals`, `reason` (`quota`, `stuck`, `stopped`, `verifier`, `failed`), `meter`, `actions` (`start`, `stop`, `retry`, each with `enabled` and `why`), `poll`.

| Case | Display state | Reason label and text | Meter | Retry | Stop |
|---|---|---|---|---|---|
| normal, judge | `awaiting-qa` | none | ledger rows or a dash | disabled (passed) | disabled |
| quota | `quota-wait` | "Quota used up", the ledger's own `QuotaExceeded` text | one row from that text, ILLUSTRATIVE | disabled until 00:00 UTC of the next day, with the reset text | disabled |
| stuck | `stuck` | "Stuck in a loop", `stop_reason=stuck after the same tool call three times` and the repeated tool; the three identical rows are marked | ledger rows or a dash | enabled | disabled |
| owner stop | `failed` | "Stopped by owner" | as above | enabled | disabled |
| running | the flow state | none | as above | disabled | enabled |

- Meter: the quota scenario's row is parsed from the real ledger's message (the throwaway ledger of `ScriptedRunner`), so the numbers are ILLUSTRATIVE and marked so; the spec's 199,400 of 200,000 is not used. Otherwise the rows are today's `tokens_per_day` per model from the machine's ledger file (`ARGUS_WORKBENCH_LEDGER`, default `.local/quota-ledger.json`) against `docs/quotas.md`, summed over tenants; a missing, unreadable or other-day file gives no rows and the page shows a dash and says why. A model with no quota row shows "no quota row", never 0 percent.
- The Retry rule in the view (`retry_action`) repeats the one in `RunManager.retry`; `test_retry_button_matches_what_the_server_does_in_every_scenario` posts the retry for all five scenarios and compares it with the view. The reset is the next 00:00 UTC after the stop (the ledger rolls its day on the UTC date), never a made-up time.
- Found while building this: on Windows the poll (a read of `trajectory.jsonl`) blocked the runner's `os.replace` and killed the run (`PermissionError: [WinError 5]`, seen in the browser). `store._retry_if_busy` now retries a busy read or replace for about half a second. `tests/test_store_busy.py` reproduces it (it fails with the retry loop removed).
