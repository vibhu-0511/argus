## P5-T04 Eval runner and results JSON

New components:

- `eval.runner`: `run_eval(tasks, agent, config)` runs an agent callable (`Task -> Outcome`) over a task list, times each task, and returns a `Results`. `AgentConfig` names the agent factory (`module:function`).

New components:

## P5-T16 Regression gate

New components:

- `eval.gate`: `compare(run, baseline, config)` returns a verdict with one line per check; `gate_main` is the CLI body. Resolve rate: the run's rate must be at or above the baseline's Wilson lower bound (minus a margin), so a drop that stays inside the baseline's interval is not a regression. Tokens per bug: `tokens_in + tokens_out` per scored task may grow only by a set fraction.
- `gate.toml`: the only place the thresholds live (interval `z`, `margin`, `max_growth`). `--config` points at another file of the same shape.
- `python -m eval gate <results.json> --baseline <baseline.json>`: prints the verdict; exit 0 pass, 1 regression, 2 input could not be read.
- `fixtures/gate/`: `baseline.json` (the real P3 variant A numbers, 20/29) and `worse.json` (made up, 12/29). Its README says which is which.

Links to existing components:

- `eval.gate` -> `eval.results.Results` (reads two results files) and `eval.stats.wilson` (baseline lower bound at the config's `z`)
- `python -m eval gate` -> `eval.__main__` (one subcommand registration)
- CI workflow (T17, later) -> `python -m eval gate`; ADR-017 (T18) sets the values in `gate.toml`

Files: `packages/eval/src/eval/gate.py`, `packages/eval/gate.toml`, `packages/eval/fixtures/gate/{baseline.json,worse.json,README.md}`, `packages/eval/tests/test_gate.py`.

## P5-T06 OTel spans for model calls, tool calls and agent runs

New components:

- `argus_core.telemetry`: `start_tracing(exporter=None)` starts a tracer provider (console exporter by default; `_default_exporter` is the one place T07 swaps in OTLP) and tags every span with the resource attribute `argus.trace.schema_version`. Helpers: `traced_agent` (decorator giving `invoke_agent {name}`), `chat_span` + `record_completion` (`chat {model}`), `tool_span` + `record_tool_error` (`execute_tool {name}`).
- Each `chat` span carries model, input/output/cached token counts, response id and model, finish reason (when the reply has one), provider, server address and port, and `argus.usage.cost_usd`. A model with no price in `prices.json` leaves that one attribute out and the run goes on.
- With no provider started the OpenTelemetry API gives no-op spans, so behaviour is unchanged. Message text is never put on a span.

Links to existing components:

- `chat` span -> `ModelClient.complete` (`argus_core/client.py`) and `_ask` in `fix_loop/loop.py` and `repro_agent/loop.py`. The loop opens the span with the step index; the client joins it and adds the endpoint details. A bare `ModelClient.complete` call (the bench baseline) gets its own span.
- `execute_tool` span -> the tool dispatch in `run_fix` and the `run_trees` call in `run_repro`.
- `invoke_agent` span -> `run_fix` and `run_repro`; `argus.stop_reason` is the loop's `StopReason`.
- cost -> `argus_core.prices.dollar_equivalent`.

Files: `packages/argus-core/src/argus_core/telemetry.py`, `client.py`, `packages/fix-loop/src/fix_loop/loop.py`, `packages/repro-agent/src/repro_agent/loop.py`; tests `packages/argus-core/tests/test_telemetry.py`, `packages/fix-loop/tests/test_otel_spans.py`.

## P5-T12 Router

New components:
- `routing.yaml` - the routing policy as data: stage -> tier, tier -> primary route and an optional fallback route (model and host), and which refusals trigger the fallback.
- `Router.complete(stage, messages)` - picks the tier for the stage, calls the host's `ModelClient` through the `Ledger`, and returns a `Routed` (completion, stage, tier, host, model, `fell_back`).
- `Routed.trace()` - the `tier`, `host` and `model` fields to copy onto a `TrajectoryStep`, so the ablation (T14) can split tokens and quota by tier.
- `UnknownStage` - a stage with no row in the policy is an error, not a default tier.

Links to existing components:
- `Router` -> `ModelClient` (one per host, passed in) and `Ledger.call` (quota check before the HTTP call; a `QuotaExceeded` or an HTTP 429 sends the call to the tier's fallback route once).
- `TrajectoryStep` -> new optional `tier`, `host`, `model`; older records omit them and still load; `trajectory.schema.json` regenerated.
- primary models -> `prices.json` (both are priced; a test checks it).

Notes: `Router` does its own ledger accounting, so a loop that already wraps `complete` in `ledger.call` (`fix_loop.loop._ask`) must pass the router's output through without a second ledger call. That wiring is T14. Mistral's model id in the fallback is not confirmed and has no quota row yet, so the ledger refuses it until `docs/quotas.md` gets one.

Files: `packages/argus-core/src/argus_core/{router.py,routing.yaml,types.py}`, `packages/argus-core/schemas/trajectory.schema.json`, `packages/argus-core/tests/test_router.py`.

## P5-T08 Attribute normalizer

New components:
- `NormalizingExporter(inner, profile)` (`argus_core/trace_normalize.py`) - wraps whichever exporter T07 chose; each span is rebuilt with the profile's attribute names before it is exported. Name, parents, status, events and times are copied unchanged.
- `PROFILES` - the mapping table in code: argus attribute -> (backend attribute, optional value change). `langfuse`: cost to `gen_ai.usage.cost`, run id to `langfuse.session.id`, five argus attributes to filterable `langfuse.observation.metadata.*`. `phoenix` (OpenInference): operation to `openinference.span.kind` (chat to LLM, execute_tool to TOOL, invoke_agent to AGENT), model, provider, token counts, cost, session, tool and agent names. `none`: no change. A mapped attribute is moved, not copied.
- `KNOWN` and `unmapped` - every name argus emits. Any other name passes through unchanged and is counted by name in `NormalizingExporter.unmapped`; `telemetry.unmapped_attributes()` returns it. The log warning (once per name) carries the name, never the value. This is what T24 relies on.
- `ARGUS_TRACE_PROFILE` - `langfuse`, `phoenix` or `none`; default is `langfuse` for the Langfuse backend and `none` otherwise.

Links to existing components:
- `_default_exporter()` -> `NormalizingExporter` -> OTLP or console exporter. A test passing its own exporter to `start_tracing` still gets raw spans.
- Rules read the names in `docs/notes/p5-semconv.md`. The Langfuse targets come from the Langfuse OTel page (read 2026-11-01), the Phoenix targets from the OpenInference semantic conventions; neither was checked against a running Langfuse. Phoenix is checked in T09.

Notes: the old names `gen_ai.system` and `gen_ai.usage.prompt_tokens` are not aliased, because argus never writes them; if a span carries one it is counted as unknown. Langfuse already infers observation type from `gen_ai.operation.name`, so no `langfuse.observation.type` rule was added.

Files: `packages/argus-core/src/argus_core/trace_normalize.py`, `telemetry.py`; test `packages/argus-core/tests/test_trace_normalize.py`.

Proof: `uv run pytest packages/argus-core/tests/test_trace_normalize.py -q`

## P5-T20 (prep) Multimodal run: checkout, prompt, patch capture, honest results
