## P5-T02 Trajectory metrics definitions

New components:

- `docs/metrics.md`: the five trajectory metrics (steps, tool-error rate, redundant-call rate, stuck rate, recover-after-gate-failure rate) as exact formulas over a `trajectory.jsonl`, the rule for pooling them over many runs, and one worked example by hand.

Links to existing components:

- metrics definitions -> `argus_core.types` (`Trajectory`, `TrajectoryStep`: the fields the formulas read)
- stuck rule -> `fix_loop.loop` (`REPEAT = 3`: the same three-in-a-row rule, applied to the stored file)
- rejected submit -> `fix_loop.loop` and `fix_loop.gates` (a `submit` with no stop reason is one sent back after a failed gate)

Files: `docs/metrics.md`.

Proof: the worked example uses `packages/fix-loop/runs/p4b-full-summary-h10/trajectory.jsonl`; the T03 unit test recomputes it.

## P5-T03 Trajectory metrics code and CLI

New components:

- `eval` package (`packages/eval`, new uv workspace member): the home of eval code for P5.
- `eval.metrics`: `run_metrics` turns one `Trajectory` into counts, `summarize` pools counts into a `MetricsSummary` (the five metrics), `load_dir` reads a directory of `trajectory.jsonl`.
- `python -m eval metrics <dir>`: prints the metrics for a directory (`--glob` to pick runs, `--json` for machine output).

Links to existing components:

- `eval.metrics` -> `argus_core.types` (reads `Trajectory.from_jsonl`)
- `eval.metrics` -> `docs/metrics.md` (the formulas it implements)
- stored runs `packages/fix-loop/runs/*/trajectory.jsonl` -> `eval.metrics` (input; nothing is written back)

Files: `packages/eval/pyproject.toml`, `packages/eval/src/eval/{__init__,metrics,__main__}.py`, `packages/eval/tests/test_metrics.py`, `packages/eval/results/stored-metrics.txt`, root `pyproject.toml` (workspace member), `uv.lock`.

Proof:

```
uv run pytest packages/eval/tests -q
uv run --package eval python -m eval metrics packages/fix-loop/runs --glob 'p3-*/trajectory.jsonl'
```

Stored result (`packages/eval/results/stored-metrics.txt`): P3 29 runs, tool-error rate 0.1111, redundant-call rate 0.0000, stuck rate 0; P4 264 runs, 0.0914, 0.0205, 0.0038. The recover rate is n/a for both: no stored run has a rejected submit.

## P5-T04 Eval runner and results JSON

New components:

- `eval.runner`: `run_eval(tasks, agent, config)` runs an agent callable (`Task -> Outcome`) over a task list, times each task, and returns a `Results`. `AgentConfig` names the agent factory (`module:function`).
- `eval.results`: the results JSON models and their JSON Schema. This is the contract that the report (T05), gate (T16), multimodal run (T19, T20) and dashboard (T21) read.
- `eval.stats`: `wilson` (95% interval, z = 1.96) and `percentile` (linear interpolation).
- `eval.stub`: stub agent with no model call, for tests and dry runs.
- `python -m eval run` and `python -m eval schema`: write one results JSON; print the schema.

Links to existing components:

- `eval.runner` -> `argus_core.types.Task` (the task list) and `eval.metrics` (fills `trajectory_metrics` from the rows that give a trajectory path)
- `eval.stats.wilson` -> same formula as `fix_loop.baseline._wilson` (test reproduces the P3 cell 20/29 = [0.507695, 0.827246])
- results JSON -> report (T05), gate (T16), dashboard (T21): read only
- `$_equivalent` -> price table (T11): stays `null` here; no dependency on it

Files: `packages/eval/src/eval/{stats,results,runner,stub,__main__}.py`, `packages/eval/schemas/results.schema.json`, `packages/eval/schemas/results.example.json`, `packages/eval/README.md` (field table and rules), `packages/eval/tests/test_runner.py`.

Proof:

```

uv run --package eval python -m eval schema
```
