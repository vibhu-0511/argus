# P4 architecture

Source: `phases/P04-verify.md`. The checks, the judge runner, and best-of-k are in `packages/verify`. The submit gate is `verify` on `run_fix`.

## Order

`pixel`, then `overflow`, then `axe`, then `console`. A hard failure returns one verdict and does not run the rest. ADR-012. The judge is not in that list.

## What was measured

The unit tests cover a clean pass and a matching failure for each check, the published Krippendorff example (α = 0.692), the short-circuit, the one retry on the fix loop, and the CI pair gate. They do not call a model.

The 100-pair set is on disk (real Canvas screenshots, 20 tickets) with blank human labels and a separate file of Claude's draft labels for the owner to review. Ollama and `gemma4:e4b` are installed; the baseline judge run was started and no α is recorded. Rows C to E have a 3-task pilot (oracle selector, `claude-session`); rows A and B have no result. Held-out α is null. ADR-013 keeps the judge advisory. ADR-014 keeps default k at 1 and the cap at 5. Details: `docs/notes/p4-finish.md`.
