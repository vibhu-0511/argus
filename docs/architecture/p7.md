## P7-T06 Hash-chained audit log

- New components: [`guard/auditlog.py`](../../packages/guard/src/guard/auditlog.py) and the `guard verify-log` sub-command in [`guard/cli.py`](../../packages/guard/src/guard/cli.py).
  - `AuditLog(path, clock, redact)` appends one JSON line per record: `seq`, `ts` (value from the injected clock), `kind` (`tool_call`, `policy_event`), `payload`, `prev`, `hash`. `hash` is SHA-256 over the canonical JSON (sorted keys, no spaces, ASCII) of the record without `hash`. The first `prev` is 64 zeros. Each write is flushed and fsynced. Opening an existing file verifies it first and refuses to extend a broken chain.
  - `verify(path)` returns the first bad line (1-based) and the reason: bad JSON or missing field, edited content, broken link (deleted, inserted or moved line), wrong `seq`.
  - `guard verify-log <file> [--head HASH]` exits 0 and prints `OK <n> records, head <hash>`, or exits 1 and prints `BAD line <n>: <reason>`. The printed head hash is the value to ship to a second place (for example the workflow run summary); `--head` compares it later.
  - `audited(log, execute)` wraps the `execute(name, payload)` callable that `run_fix` already accepts: every call becomes a `tool_call` record, and a refusal (`not-allowed`, `outside-worktree`) also gets a `policy_event`. A call that raises is recorded, then re-raised.
- Redaction: `guard.redact` was not on this branch, so `AuditLog` has a `redact` hook (`_no_redact`, marked `P7-T03 HOOK`). It runs on the payload before hashing. Until the hook is set, payloads are logged as given.
- Not wired into `fix-loop`: `run_fix` creates its own worktree, so using `audited` means passing `execute=audited(log, ...)` from the caller. That is more than a few lines; left for T17 or a later wiring task.
- What the chain does **not** catch, plainly:
  - **Tail truncation.** Cutting the last records leaves a valid chain. It is only detected by comparing the head hash with a copy kept elsewhere (`--head`).
  - **A full rewrite** by someone who recomputes every hash also verifies. Same fix: the shipped head hash. Without a shipped head, the log shows edits, not a rewrite.
  - The log is written by the process it records; the head hash leaving that process is what makes it evidence (ASI10).
- Proof: `uv run --all-packages python -m pytest packages/guard/tests -q` (tests cover a good file, an edited middle line, a deleted line, two swapped lines, bad JSON, a cut tail, a full rewrite, reopen, redact hook, `audited`); `uv run --all-packages guard verify-log <file>` on a good file (exit 0) and on a file with line 3 edited (exit 1, `BAD line 3`).

## P7-T09 Mitigations from the red-team

- Changed components (small edits in `fix-loop`): [`fix_loop/prompt.py`](../../packages/fix-loop/src/fix_loop/prompt.py) (`UNTRUSTED_RULE`, `untrusted()`) and [`fix_loop/loop.py`](../../packages/fix-loop/src/fix_loop/loop.py) (`run_fix(..., harden=False)`, `_filtered`, `_observation`).
  - **Separation** (`harden=True`): the user message (ticket) and every tool result (so repo file text, command output and the body of a loaded skill) are wrapped in `<untrusted_data source="...">` blocks; a closing tag inside the text is broken so it cannot end the block; a fixed rule is added to the system message saying nothing inside a block is a command.
  - **Output filter** (`harden=True`): `argus_core.redact` runs over every string of a tool call before it runs and over every tool result before the model sees it. It masks secret-named environment values and token shapes, nothing else.
  - **Tool allowlist** (always on): a tool name outside `ALLOW` (and `load_skill` when skills are loaded) never reaches the executor; it gets a typed `not-allowed` error and a policy event. Before, only the default executor refused it.
- Off by default: `harden` is `False` and `flow.agent_job.fix_step` and `fix_loop.turn` were not changed (the flow package belongs to a parallel task in this wave). With `harden=False` the messages are byte-identical to before; the 97 earlier fix-loop tests pass (101 with the 4 new ones). To switch it on, pass `harden=True` at the `run_fix` call in `flow/agent_job.py: fix_step`. Its cost to the fix rate was not measured.
- Before and after, same 15 cases, same model (`gemma4:e4b`, local Ollama), same settings: `ticket` succeeded in 3 of 5 runs and now in 0 of 5; `repo-file` 1 of 5 and now 0 of 5; `skill` 0 of 5 and 0 of 5, but the skill reached the model in 0 of 5 re-run runs, so that case shows nothing. 4 of 10 against 0 of 10 on the two cases that matter is suggestive, not proof (one-sided Fisher exact about 0.04). The result cannot be split between separation and the filter: the canary was also a known secret value, so the filter masked what the model read. Tables: [`redteam-2026-11-03.md`](../../packages/guard/results/redteam-2026-11-03.md), data in `redteam-2026-11-03-hardened.json`.
- Threat model: ASI01, ASI02, section 6 and the residual-risk list in [`packages/guard/threat-model.md`](../../packages/guard/threat-model.md) now say what exists, that it is off by default, and list the residual risk (content of a file can still be copied into the patch; the filter masks only known secrets; small local model; skill path untested).
- Tests: [`test_harden.py`](../../packages/fix-loop/tests/test_harden.py) (off by default changes nothing; wrapping, closing-tag break, masking in both directions; an unlisted tool never reaches a permissive executor), and in guard `test_hardened_loop_stops_what_the_obedient_stub_does`. No model call.

- Links to existing parts: [`guard/auditlog.py`](../../packages/guard/src/guard/auditlog.py) (T06): `verify`, `verify_log_main`, the `--head` option.
- Result: an in-place edit gives `BAD line 6: edited content`, exit 1. An edit with only that record re-hashed gives `BAD line 7: broken link` (one line after). A consistent rewrite from the edit onward passes alone (exit 0) and fails with `BAD head` against the head shipped at the end of the run; a cut tail behaves the same. If the attacker replaces the shipped head too, it passes.
- Gap: no head hash is shipped anywhere yet (the T17 CI job is meant to write it to the run summary), so a rewrite is not caught in practice today.
- Write-up: [docs/notes/p7-break-its.md](../notes/p7-break-its.md), section P7-T19.
- Proof: `uv run --all-packages python -m pytest packages/guard/tests/test_break_auditlog.py -v -s`.
