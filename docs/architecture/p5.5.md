# P5.5 architecture

Source: `phases/P05.5-argus-skills.md`. P5.5 distils reusable skills from successful trajectories, loads them on demand (progressive disclosure), measures whether they help on held-out bugs, and shows that a poisoned skill cannot take over the agent. ## P5.5-T03 Train and held-out split

The held-out set is the 30 seeded tasks (29 runnable). The train set is 40 generated mutants. A script proves the two sets share no task id and no (source file, operator) pair, so a skill learned on train cannot be a copy of a held-out bug.

New components:

- `skills.split` (`packages/skills/src/skills/split.py`) builds the split, derives each task's (file, operator) pairs from its `bug.patch`, and checks the result.
- `split.json` (`packages/skills/split.json`) is the committed answer: held-out ids with a `runnable` flag, ordered train ids, the selection rule, the pairs, the counts.
- `skills` Python package, a new member of the root uv workspace (stdlib only).

Links to existing components:

- `skills.split` -> `packages/bench/tasks/seeded` and `packages/bench/tasks/mutated` (reads `meta.json`, `bug.patch`).
- `skills.split` -> bugsmith operator list (`OPERATOR_ARCHETYPE`, `docs/bug-archetypes.md`) for the archetype-to-operator fallback.
- `split.json` -> T04 trajectory collection (runs `train` in order) and T08 ablation (runs `held_out` where `runnable`). Same 29 tasks as `eval.ablation tasks`.

Files: `packages/skills/{pyproject.toml,README.md,split.json,src/skills/{__init__,split}.py,tests/test_split.py}`, `docs/notes/p5.5-t03.md`, `pyproject.toml` and `uv.lock` (workspace member).

Proof: `uv run pytest packages/skills/tests -q` and `uv run python -m skills.split check` (exit 1 on a shared id, a shared pair, or a stale `split.json`).

## P5.5-T04 Training trajectories

20 successful fix runs on train mutants, with Claude sessions as the model (one fresh sonnet subagent per loop step, fix stage only). They are the raw material for the T05 draft script.

New components:

- Variant `T` of `eval.t14_turn` (`packages/eval/src/eval/t14_turn.py`): starts a task from `packages/bench/tasks/mutated`, runs under `packages/eval/runs/p55-t04/<task id>/`, skips the repro stage, and writes `diff.patch` against the bug state (HEAD plus `bug.patch`), so an exact revert is not an empty diff. A and B are unchanged.
- `skills.collect` (`packages/skills/src/skills/collect.py`) copies each resolved run to `packages/skills/trajectories/<task id>/` (trajectory, verdict, diff, ticket text), keeps only `verdict.json` of the others under `_unresolved/`, and writes `ledger.json` (steps and chars/4 token estimates per run, totals, the self-imposed budget).
- `packages/eval/swarm/coord_train.md` and `status_train.sh`: coordinator instructions and a status line for variant T.

Links to existing components:

- `eval.t14_turn` T -> `fix_loop.run_fix` (stage `fix`, strategy `cap`, budget 32,000), `argus_bench score` (the verdict), `policies/claude-strong-only.yaml` (every stage on the strong tier).
- `skills.split` (`split.json` `train` order) -> the runs. `trajectories/` -> T05 (distil a draft skill per success) and T08 (no held-out task was run).
- Budget: `eval.t14_turn.SELF_IMPOSED` (300 requests, 10 million tokens per model). A self-imposed budget only: Claude sessions have no provider cap, so `ledger.json` is built after the fact and never refuses a call.

Files: `packages/eval/src/eval/t14_turn.py`, `packages/eval/tests/test_t14_turn.py`, `packages/eval/swarm/{coord_train.md,status_train.sh}`, `packages/skills/src/skills/collect.py`, `packages/skills/tests/test_collect.py`, `packages/skills/trajectories/**` (data commit), `docs/notes/p5.5-t04.md`.

Result: 22 runs started, 21 with a verdict, 20 resolved (11 font-size, 9 missing-style), 1 excluded by the scorer (exit 2), 1 stopped at the 20-resolved mark.

Proof: `uv run pytest packages/eval/tests/test_t14_turn.py packages/skills/tests -q`, and `python -m skills.collect` (rewrites `ledger.json` from the run folders; see the note on `mut-0201` before re-running it).
