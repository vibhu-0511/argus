# P5.5 architecture

Source: `phases/P05.5-argus-skills.md`. P5.5 distils reusable skills from successful trajectories, loads them on demand (progressive disclosure), measures whether they help on held-out bugs, and shows that a poisoned skill cannot take over the agent. ## P5.5-T03 Train and held-out split

The held-out set is the 30 seeded tasks (29 runnable). The train set is 40 generated mutants. A script proves the two sets share no task id and no (source file, operator) pair, so a skill learned on train cannot be a copy of a held-out bug.

New components:

- `skills.split` (`packages/skills/src/skills/split.py`) builds the split, derives each task's (file, operator) pairs from its `bug.patch`, and checks the result.
- `split.json` (`packages/skills/split.json`) is the committed answer: held-out ids with a `runnable` flag, ordered train ids, the selection rule, the pairs, the counts.
- `skills` Python package, a new member of the root uv workspace (stdlib only).

Links to existing components:

- `skills.split` -> `packages/bench/tasks/seeded` and `packages/bench/tasks/mutated` (reads `meta.json`, `bug.patch`).
- `skills.split` -> bugsmith operator list (`OPERATOR_ARCHETYPE`, `docs/bug-archetypes.md`) for the archetype-to-operator fallback.
- `split.json` -> T04 trajectory collection (runs `train` in order) and T08 ablation (runs `held_out` where `runnable`). Same 29 tasks as `eval.ablation tasks`.

Files: `packages/skills/{pyproject.toml,README.md,split.json,src/skills/{__init__,split}.py,tests/test_split.py}`, `docs/notes/p5.5-t03.md`, `pyproject.toml` and `uv.lock` (workspace member).

Proof: `uv run pytest packages/skills/tests -q` and `uv run python -m skills.split check` (exit 1 on a shared id, a shared pair, or a stale `split.json`).

## P5.5-T02 Skill loader

Progressive disclosure inside the fix loop. The system message lists each loadable skill's name and description (level 1). The model calls `load_skill` to get one body (level 2). A catalog of 20 skills adds 880 estimated tokens to the prompt; their 20 bodies are 23,280 (test fixture, `len // 4`).

New components:

- `skills.load_skills` (`packages/fix-loop/src/fix_loop/skills.py`) reads `<dir>/<name>/SKILL.md`, checks the format and returns `(loadable skills, refusals)`. Each refusal has a typed `Reason` and is logged.
- `skills.trust_refusal` is the single place that decides loadable vs refused on trust. It refuses nothing today; T10 fills it (review flag, lock hash, tool allowlist).
- `skills.catalog` builds the level-1 block: names sorted, name and description only, no body, no path, two lines telling the model to call `load_skill`.
- `skills.load_skill` and `skills.tool_spec`: the call returns the body as `<skill_content name="...">`, a second call for the same name returns an "already loaded" note, a name outside the enum is `not-found`. `tool_spec` is the JSON schema with `name` as an enum.
- `skills.loaded_names` lists the skills a run loaded from its stored trajectory steps (a step with `tool_name == "load_skill"` whose text starts with the wrapper), so "skills loaded per run" needs no schema change.

Links to existing components:

- skills loader -> `run_fix` (new `skills: Path | None` argument): `load_skills` runs once at the start, `load_skill` answers the call before the normal tools, the catalog goes into the system message.
- `skills.catalog` -> the system message in `run_fix`: the catalog is appended after `system_message(instruction)`, last. With no skills the bytes are the same as before; the same skill set gives the same bytes (the P5-T13 cache-prefix property).
- `load_skill` step -> `argus_core.types.TrajectoryStep` (`tool_name`, `message`, ADR-001): no new field.
- `MAX_BODY_CHARS = 8000` is defined once here; the T12 lint imports it.
- `fix-loop` now depends on PyYAML (already in `uv.lock`).

Files: `packages/fix-loop/src/fix_loop/{skills,loop}.py`, `packages/fix-loop/pyproject.toml`, `uv.lock`, `packages/fix-loop/tests/test_skills.py`.

Proof: `uv run pytest packages/fix-loop/tests/test_skills.py -q -s` (the `-s` prints the 880 vs 23,280 token numbers).

## P5.5-T05 Draft script

Turns successful stored trajectories into candidate skills with the cheap-tier model. Every draft is marked unreviewed and is not loadable until T10's checks pass it.

New components:

- `skills.draft` (`packages/skills/src/skills/draft.py`): `successes` picks resolved train runs, `render_run` shortens a run to prompt text, `draft_group` makes one model call per group and writes `packages/skills/skills/<name>/SKILL.md`, `main` is the command line (`--dry-run` lists groups with no model call).
- The script writes the frontmatter, not the model: quoted `description`, fixed `allowed-tools` (no `run_cmd`), `metadata` `argus-status: "unreviewed"`, `argus-archetype`, `argus-sources`.

Links to existing components:

- `skills.draft` -> `split.json` (T03): only `train` ids are used, so a held-out task cannot feed a skill.
- `skills.draft` -> T04 stored runs (`verdict.json` + `fix/trajectory.jsonl`) read with `argus_core.types.Trajectory`.
- `skills.draft` -> `argus_core.client.ModelClient` (any OpenAI-compatible host; the cheap tier in `routing.yaml` is the intended model).
- `skills.draft` -> `fix_loop.skills._parse` (T02): a reply that fails the loader's format check, or the body limit, is not written. `skills` now depends on `argus-core` and `fix-loop`.

## P5.5-T10 Skill trust controls

The loader now refuses a skill unless the owner has reviewed it and the file is byte-for-byte what was reviewed, and the agent can use only the tools the loaded skills allow.

New components:

- `skills.trust_refusal` (`packages/fix-loop/src/fix_loop/skills.py`): review flag, hash pin, tool names, with typed reasons `unreviewed`, `not-pinned`, `hash-mismatch`, `tool-not-allowed`.
- `skills.content_hash` and `skills.read_lock`: the pin definition (SHA-256, CRLF read as LF) and the reader of `skills.lock.json` (a bad lock trusts nothing).
- `skills.tool_denied`: the run-time allowlist, the loop's tools intersected with the `allowed-tools` of every loaded skill (`submit` and `load_skill` always pass; no loaded skill, no limit).
- `skills.lock.json` (`packages/skills`): the trust anchor, one entry per reviewed skill. Empty today.
- `skills.pin` (`packages/skills/src/skills/pin.py`): the owner's sign-off command; writes the entry only if the loader would accept the skill.

Links to existing components:

- `trust_refusal` <- `_load_one` (T02) is the only caller; a refusal leaves the skill out of `catalog` and `tool_spec`.
- `tool_denied` <- `run_fix` (`loop.py`): checked before every tool call except `load_skill`; a denied call is a `ToolError` (`not-allowed`, message `tool-not-allowed: ...`) stored in the trajectory like any tool error.
- `allowed-tools` names -> `fix_loop.tools.ALLOW`.
- T05 drafts have no lock entry, so they are `unreviewed` until `skills.pin` runs.
- T12 (lint) and T13/T14 (break-its) read the same reasons and `content_hash`.

Files: `packages/fix-loop/src/fix_loop/{skills,loop}.py`, `packages/fix-loop/tests/{test_skills,test_skill_trust}.py`, `packages/skills/{skills.lock.json,src/skills/pin.py,tests/test_pin.py}`, `docs/notes/p5.5-t10.md`.

Proof: `uv run --all-packages python -m pytest packages/fix-loop/tests/test_skill_trust.py packages/skills/tests/test_pin.py -v`.

## P5.5-T12 Skill lint in CI

A CI job that checks every skill file and the hash lock with no model and no network. It fails the build on a bad skill, so a bad file cannot reach the loader through a merge.

New components:

- `skills.lint` (`packages/skills/src/skills/lint.py`) walks `packages/skills/skills/<name>/SKILL.md` and prints one line per problem as `<skill>: <typed reason>: <detail>`. Exit 1 on any problem.
- `skills-lint` workflow (`.github/workflows/skills-lint.yml`) runs the lint tests and the lint on a push or pull request that touches `packages/skills/**` or `fix_loop/skills.py`.

What it checks: frontmatter (missing or unclosed, unknown field, repeated key, bad `name` or `metadata`), body over 8,000 characters, any file next to `SKILL.md`, and the lock file (entry missing, `sha256` not 64 lowercase hex, hash not equal to the file, entry for a skill that is gone).

Links to existing components:

- `skills.lint` -> `fix_loop.skills` (`_parse`, `MAX_BODY_CHARS`, `Reason`): the format rules and the size limit are imported, not copied, so the loader and the lint cannot disagree. `packages/skills` now depends on `fix-loop`.
- `skills.lint` -> `packages/skills/skills.lock.json`: shape and hash definition (CRLF to LF, then SHA-256 of the whole file) from `docs/notes/p5.5-t01-skills-spec.md` section 4. The lock file itself is written by T10 and T06.
- When T10 lands, the lint should call T10's lock reader and hash function in place of its own `_read_lock` and `_hash`, and add the three review-flag checks the T01 notes list for the lint (`argus-status` against `reviewed`, `argus-archetype` when reviewed, `argus-sources` against the held-out ids).

Files: `packages/skills/src/skills/lint.py`, `packages/skills/tests/test_lint.py`, `packages/skills/pyproject.toml`, `uv.lock`, `.github/workflows/skills-lint.yml`, `docs/notes/p5.5-t12.md`.

Proof: `uv run pytest packages/skills/tests/test_lint.py -q` (a good skill and one bad skill per rule) and `uv run --package skills python -m skills.lint` (exit 0 today: no skills yet).
