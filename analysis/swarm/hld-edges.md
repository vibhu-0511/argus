# Problem, solution, HLD and edge cases

Lane `problem-hld-edges`. Source of truth for the JSON twin `hld-edges.json` (same content, generated from one data file). Docs and analysis only; no code was changed. `built` = code read under `packages/`; `planned` = described in a phase doc. Numbers without a run id are not stated.

## 1. Problem

A UI bug ticket (text, maybe a screenshot) is cheap to file and expensive to act on: someone has to reproduce it in a browser, map the broken pixels back to a source file, change code without breaking other screens, and prove the change fixed what the ticket described. Argus automates that chain and hands back a pull request that carries its own evidence, so a human reviews a verified diff instead of starting from a sentence.

### Who hurts

| Who | Pain | Source |
| --- | --- | --- |
| Front-end and full-stack engineers who triage UI tickets | Reproduction is manual (open the app, find the route, click through), and the ticket often names neither route nor element. | PROJECT.md:3, PROJECT.md:15 |
| QA / reviewers who must trust a fix | A green unit-test run does not show that the pixels, layout or accessibility of the screen are right; they need a before/after artifact, not an assertion. | PROJECT.md:18, PROJECT.md:19 |
| The project owner (learner, backend background) | Needs the agentic layer built end to end, measured, at $0 and 20 h/week, with every number backed by a run. | PLAN.md:3, PLAN.md:11-13 |

### Why UI-bug triage is costly

- Reproduction needs a live browser and the exact route/state; the ticket rarely supplies it. (PROJECT.md:15)
- DOM to source mapping is not free: React 19 removed _debugSource, so a build-time data-src attribute is the route. (PROJECT.md:16, PLAN.md:63)
- 'Fixed' is a visual claim: pixel, overflow, accessibility and console regressions on other routes must be ruled out, not only the target element. (PROJECT.md:18, phases/P04-verify.md:60)
- Every step is stochastic when a model does it, so each stage needs an oracle that does not use a model. (PROJECT.md:198)

## 2. Solution: five stages, one invariant each

Five stages, each with an invariant that a deterministic oracle checks before the next stage may start. Models propose; scripts, sandboxes and ledgers dispose. State is durable where a side effect leaves the machine (PR, comment, dispatch) and GitHub is the source of truth.

| Id | Principle | Source |
| --- | --- | --- |
| SP1 | Oracle before model: every stage's pass/fail is decided by code (verifier, scorer, check run), not by a model's opinion. | PROJECT.md:17-18 |
| SP2 | Quota is a hard stop, checked before the HTTP request, per model id; unknown model is refused. | packages/argus-core/src/argus_core/ledger.py:80-97, docs/adr/0002-quota-ledger-semantics.md |
| SP3 | Replayable evidence: a trajectory stores every step so a run can replay with no model call. | packages/argus-core/src/argus_core/types.py:95-132 |
| SP4 | Webhooks are hints; GitHub is the source of truth; a poller repairs lost events. | PROJECT.md:11, PLAN.md:343 |
| SP5 | External side effects are find-or-create on a stable key, so a retry after a crash cannot duplicate them. | phases/P06-argus-flow.md:57, analysis/verification_report.md:13 |
| SP6 | The agent runs where it can do the least harm: no network, bench checks read-only, no repo token in its environment. | PROJECT.md:17, phases/P08-argus-app.md:40 |

### S1 Reproduce (P1, built (plumbing); live path not wired)

- **Input:** Ticket {id, text, optional screenshot}
- **Output:** repro.spec.ts (Playwright script) + trajectory.jsonl + verdict
- **Invariant:** The script must fail on the buggy tree and pass on the golden tree; test.skip/test.fixme is an error; no snapshot ref, no page.evaluate; the script must contain a symptom assertion.
- **Enforced by:** verify() packages/repro-agent/src/repro_agent/verify.py:23-30; _problem() packages/repro-agent/src/repro_agent/loop.py:179-186; loop stop at packages/repro-agent/src/repro_agent/loop.py:104-108
- **Checks before judge:** n/a (no judge at this stage)
- **Stops:** submit, retry-cap, QuotaExceeded, tool-unavailable, stuck (bad screenshot bytes)
- **Caveat:** Tree execution is an injected callable (run_trees). Only fixture implementations exist: batch.py hard-codes the outcome and replay.py always returns (True, True). No code runs a model-written script on the two trees in Docker. On a live ticket there is no golden tree before the fix exists, so the invariant must be split into 'fails on HEAD' now and 'passes after the patch' at Verify (design gap, see edge case EC-13).
- **Sources:** packages/repro-agent/src/repro_agent/loop.py:44-121, packages/repro-agent/src/repro_agent/batch.py:89-97, packages/repro-agent/src/repro_agent/replay.py:40, packages/repro-agent/docker/entrypoint.sh:6-9

### S2 Locate (P2, planned)

- **Input:** A failing selector or DOM node from the reproduction
- **Output:** file:line:col candidates (or a typed error)
- **Invariant:** Never return a confident wrong file: wrapper components and repeated elements return ranked candidates (ambiguous); a production build returns no-source-info; an unknown selector returns not-found. data-src exists only in dev/test builds.
- **Enforced by:** locate() typed errors; plugin tests that count missing attributes in dev and assert none in production (P2-T03, T08, T15, T16)
- **Checks before judge:** n/a
- **Stops:** not-found, ambiguous, no-source-info
- **Sources:** phases/P02-dom2src.md:38-43, phases/P02-dom2src.md:50-52, PROJECT.md:218

### S3 Fix (in sandbox) (P3, planned)

- **Input:** Ticket + repro script + locate() hint + AGENTS.md
- **Output:** A diff in a git worktree + trajectory
- **Invariant:** All edits happen in a per-task git worktree inside Docker with --network none and CPU/memory caps; bench check files are read-only; edit is an exact unique match; gates (build, typecheck, lint, unit, bench checks) run before submit and failures return as structured messages; a malformed tool call is a typed error, never a crash; any stop still scores the worktree diff.
- **Enforced by:** P3-T02 (tool schemas), T05 (sandbox), T06 (stop conditions), T14-T15 (gates), T31 (edit-the-checks break-it)
- **Checks before judge:** n/a
- **Stops:** submit, step-cap, token-cap, QuotaExceeded, stuck, consecutive-timeout
- **Sources:** phases/P03-fix-loop.md:38-51, phases/P03-fix-loop.md:58, packages/argus-core/src/argus_core/types.py:74-82

### S4 Verify (P4, planned)

- **Input:** Candidate patch(es) + before/after screenshots + ticket
- **Output:** One structured verdict (per-check results, first failure, judge label)
- **Invariant:** Deterministic checks run first in a fixed order and short-circuit on the first hard failure: pixel diff, overflow, axe (new violations only), console (new errors and warnings). Only then a cross-family vision judge. The judge does not override a passed check run. Best-of-k lives inside the selector. A rejected patch gets one retry with the verdict in context. If judge alpha < 0.80 on the calibration set, the judge is advisory only.
- **Enforced by:** P4-T06 (pipeline), T12-T14 (alpha), T19 (best-of-k), T22 (retry), T23 (CI on stored fixtures)
- **Checks before judge:** yes: checks -> judge -> label recorded; the judge never flips a passed check run (PLAN-025). Open question: what a 'no-match' judge label does to a patch whose checks passed (EC-40).
- **Stops:** accept, reject (one retry), judge-unavailable (advisory)
- **Sources:** PLAN.md:120, phases/P04-verify.md:6-14, phases/P04-verify.md:41, phases/P04-verify.md:54, phases/P04-verify.md:57, analysis/verification_report.md:81

### S5 Hand back (P6 + P8, planned)

- **Input:** Accepted patch, verdict, judge label, trajectory, before/after screenshots
- **Output:** A draft pull request (find-or-create, one stable branch) then QA decision, then optional backport
- **Invariant:** One PR per ticket: created by a non-agent step, as JSON fields (never shell-interpolated), draft until QA, none on an empty patch, and a lookup error leaves the existing PR untouched. QA waits in awaiting-qa with a timeout and an idempotency key. Backport comments on conflict and never force-pushes.
- **Enforced by:** P6-T08..T10 (QA), P6-T21 (crash break-it), P8-T09 (PR creation), P8-T10 (backport)
- **Checks before judge:** n/a
- **Stops:** done, rejected, qa-timeout
- **Sources:** phases/P06-argus-flow.md:44-46, phases/P06-argus-flow.md:57, phases/P08-argus-app.md:45-46, PROJECT.md:19
