## New findings beyond the candidates (highest value first)

- The bench scorer never loads the app. `run-checks.ts` builds a fake page: `<span class="sel">` plus the one stylesheet. The five "flows" are only a label (G03).
- Mutant tickets copy the check: the ticket gives selector, property and expected value (G04).
- Nothing connects the loop to Docker, two trees and the app, and the container's entrypoint refuses any script but three fixed ones (G06).
- Retry feedback is empty: the loop does not send the model its previous script or any run output (G07).
- Quota ledgers are per run directory, so the account-wide Groq cap is not shared (G10).
- `bench` tests are red on a clean checkout (`test_golden.py:11` expects 30 tasks, finds 330) [ran] (G02).
- Baseline sends dcortex source files to a free tier whose data policy says prompts may train models (G09).

## Security smells (summary)

- Free-tier training policy vs dcortex source (G09).
- Browser can navigate anywhere (G19); container hardening (G20); `npx -y` run-time fetch (G18).
- `config/platform.md:11` commits a local user path (G01).
- Secrets: no key reads or logs in `client.py`; `baseline.py` prints only model content. `check_no_secrets.py` not wired (G25). No issue found in `ModelClient` header handling.
- `score.py` / `run-checks.ts` path handling is good: css path and baseline path are checked with `inside()` (`run-checks.ts:32-43, 166-172`), and non-local requests are aborted (`launchPage`). No finding there.
